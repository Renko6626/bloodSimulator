# 血管机器人游戏设计草案

日期：2026-10-19。状态：根据讨论整理的首版草案，尚未实施。

2026-10-20 更新：用户已要求开始搭建骨架和原型，首轮工程进展见 [实施记录](../plans/2026-10-20-implementation-log.md)。下文“本次只交付文档”描述的是 10 月 19 日的任务范围。

本文区分已确认方向、工程建议和待决问题；调研中的能力不等于已验证结果。

## 目标与制作条件

东方 Game Jam，主题为“心”。以血液循环和免疫系统构成可互动的游戏环境，让细胞物理、战斗和交通产生有趣的混乱。

- 三周、单人制作；开发者强项为高性能引擎与物理模拟。
- 桌面游戏；最终发布的操作系统与硬件预算待定。
- 2D，机器人略大于红细胞，整体保持细胞尺度。
- 背景为永远亭医疗设施，使用爱丽丝的无人机；相关内容后续补充。
- 美术、声音优先考虑程序化生成与许可明确的免费素材，可结合真实生物、医学图像参考。

“生物学 GTA”只用于描述自由行动和多方冲突的最初意象。免疫反应根据局部生物事件设计，不照搬全局通缉系统。

## 已确认的游戏体验

机器人主要靠自身推进自由移动。血流产生轻微推动，不让玩家持续失控漂流；逆行的主要阻力来自红细胞交通、碰撞和拥堵。

细胞需要真实参与可变形碰撞。玩家能被细胞挡住和推挤，也能顶开细胞、利用空隙移动。战斗包含刺击与射击，具体瞄准、伤害和武器参数尚未确定。

每关代表一次完整治疗：进入身体，经过若干血液循环，完成若干任务，从指定位置排出。目标时长 10–20 分钟；关间安排升级与过场。

清除病原体和病变组织，同时尽量减少正常组织损伤。失败条件为机器人被毁，或累计正常组织损伤达到上限。初版以一个累计损伤预算表达严重事故，不模拟完整器官衰竭。

## 已确认的免疫方向

免疫细胞起初对机器人中立。此规则不表示感染区域没有正在工作的免疫反应。

- 感染、病原体与组织损伤可引起局部免疫反应。
- 损伤位置与攻击者身份分开理解：发现损伤不等于全身免疫细胞立即知道机器人位置。
- 机器人直接攻击免疫细胞会遭到反击。
- 治疗产生的误伤有代价，玩家需要在效率、精度与风险之间取舍。

趋化、吞噬等生物机制提供设计参考。具体细胞类型、目标识别、追击解除、信号传播及攻击方式暂缓设计，不提前搭建完整免疫算法或化学场。

## 已确认的地图与模拟方向

地图采用抽象血管网络，希望保留心脏和核心器官。局部空间与整体循环之间进行尺度压缩；具体拓扑、血管口径、器官数量与区域切换仍待设计。

初版先完成细胞接触层面的堵车、挤压和疏通。血流采用以下分层：

1. **全局 0D 集总参数网络**：节点和血管段组成图，以压力、阻力和流量描述整体循环，采用类似电路的关系。
2. **局部二维流场**：接受全局边界信息，提供局部速度，先采用简化场。
3. **细胞与机器人**：流场驱动细胞；机器人受到较弱扰动，同时参与接触。

首轮为网络到局部、再到物体的单向驱动。初版堵塞不回传全局阻力，也不要求细胞成为流体求解中的移动边界。

后续研究项彼此独立：

- 局部二维流体求解器，比较网格方法与粒子方法。
- 局部细胞与流体双向作用。
- 持续堵塞改变血管有效阻力，影响网络分流。

它们不因“科学性”自动进入实施范围。二维模拟和尺度压缩用于游戏，不宣称定量还原真实血液动力学。

## 已确认的技术分工

Rust 持有唯一的模拟状态；Godot 负责表现和输入，通过 GDExtension 接入。

```text
Godot 场景、输入、绘制与界面
             ↓
Rust godot_bridge：输入与显示数据转换
             ↓
Rust simulation：物理、血管网络、流场
             ↓
Rapier：接触、刚体及优先验证的二维软体
```

- simulation 不依赖 Godot，可单独运行必要检查。
- Rust 负责后续战斗命中与受力，Godot 展示结果；这些玩法不在首轮实现。
- 同一物体不在 Godot 与 Rust 中各推进一套物理。
- 首先验证 Rapier 原生二维软体，尚未证明其密集接触表现或性能达到目标。
- 新增求解器、重要依赖或改变模块边界时，提出取舍并确认，不自动替换路线。

## 首轮工程范围

已同意的工程布局：

```text
crates/simulation/    独立 Rust 模拟库
crates/godot_bridge/  GDExtension 接入层
godot/               Godot 场景、绘制、输入与调试界面
docs/                设计、计划与使用说明
```

按三个里程碑推进：

1. **工程接通**：Cargo workspace、扩展、启动场景、构建与运行入口。
2. **软体实验场**：一段含分岔和收窄处的血管、软体红细胞、可自由移动的刚体机器人。
3. **网络驱动**：小型阻力网络、周期性压力驱动和简化局部速度场。

随上述产物加入固定时间步、明确的模拟单位与显示比例、暂停、单步、重置、集中参数、细胞数量、求解耗时、碰撞轮廓和流向显示。

当前任务只交付文档和公开 GitHub 仓库，不安装依赖、不搭建可运行工程。后续实施按工程计划推进。

## 实施者可自行处理的细节

以下是工程默认建议，不是已经确定的玩法要求：

- 用局部模拟单位表达细胞大小，渲染通过统一比例转换为像素。
- 初版采用单线程固定步进，时间步和子步数集中配置，再按测量结果调整。
- 实验场先用简单轮廓、填色和流向线显示，避免提前制作成品美术。
- 原生软体优先尝试保持面积的闭合轮廓；它是二维细胞近似，不是完整膜力学模型。
- 先用少量字段传递移动输入和物体轮廓，不搭建通用消息总线、ECS 或插件框架。
- 机器人采用推进和制动实现稳定移动，具体参数由人工体验调整。

## 验证与范围限制

验证按完整改动集中执行，以构建、扩展加载、少量关键物理检查和截图为主。操作手感由人工体验，不自动点击、填写或跑交互流程。

必要的不变量包括分支流量守恒、暂停与单步行为，以及软体在简单压缩后仍保持合理面积和恢复能力。阈值需在实际模型选定后说明依据；不为文档或低风险配置新增测试。

暂不实现关卡、敌人系统、武器、升级、存档、完整器官地图、剧情、美术资源管线、网络联机、大规模 CI、GPU 求解或完整生理病理模型。

## 调研参考

以下为前期阅读依据，未进行本地编译或性能复现：

- [Rapier Rust 二维软体](https://rapier.rs/docs/user_guides/rust/soft_bodies/)：闭合轮廓、面积保持、软体与刚体交互。
