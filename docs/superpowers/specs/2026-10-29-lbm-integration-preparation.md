# LBM 正式接入准备方案

2026-10-29。用户已阶段性同意 LSQ-FD 给定速度边界与帧末平均密度控制，并明确选择“按推荐方案接入可选 LBM 路径”。以下依赖与接口安排已确认；本方案不把纯流体实验结果等同于完整游戏验收。

## 推荐范围

沿用 blood-fluid-gpu / simulation / godot_bridge 的职责和依赖方向。在现有默认关闭的 lbm-gpu 可选路径中接入算法；默认解析流不改，Godot 不新增选项，地图开口限制不扩大。使用当前隔离工作树的 feat/lbm-lsq-integration 分支，保留实验分支与全部原始记录。

1. blood-fluid-gpu 内生成并持有 LSQ 取样索引和权重，替代实验的 Python 预计算文件。窗口创建及几何迁移时重建，单纯速度目标变化复用权重。半径 4、受给定速度约束的二次拟合、秩与条件数限制、禁止穿墙取样等数值选择沿用已验证方案。
2. 为 blood-fluid-gpu 增加项目已有的 faer 0.24.4 直接依赖，用现有 SVD 能力生成权重。无需新版本或新线性代数库；代价是该 crate 新增直接依赖关系。
3. 后端增加显式平均密度修正方法，返回修正前均值、实际采用的密度偏移及请求的质量补偿量。观测量的“请求值”和“实际测量值”明确区分，不用推算值冒充守恒验证。
4. simulation 在每帧最后一个流体 batch 延迟流场读回，全部机械子步结束后显式 finish_frame，调用修正并刷新共享采样缓存。普通中间 batch 保留现有行为；通过显式帧尾方法/参数传递时序，避免后端猜测累计步数，也避免每个机械子步都归一。补偿诊断保留在后端返回值与窗口内部可读记录中，本轮不扩大 Godot 或 snapshot 接口。
5. 保留现有每机械子步的 prepare / maybe_shift，避免遗漏子步之间的窗口迁移。迁移先生成新几何的有效 LSQ 权重，再替换相关 GPU 资源；失败明确返回错误，不增加恢复流程或回退算法。

## 主要取舍

| 安排 | 优点 | 代价 |
| --- | --- | --- |
| 推荐：后端运行时生成权重，接入可选 LBM 帧循环 | 不依赖 Python 或几何专用文件；数值逻辑集中；可直接复用现有调用路径 | 新增 faer 直接依赖及帧尾接口；需验证缓存和迁移时序 |
| 仅准备数值模块和物理文档，暂不接入帧循环 | 改动范围较小，便于之后单独安排游戏接入 | 均值控制仍需调用方手动执行，不能声称现有 LBM 游戏路径已采用新方案 |

不推荐把权重计算放进 Godot，或把 Python 离线文件当作移动窗口的正式运行依赖。也不为五列最小二乘自行实现一套替代 SVD 算法。

## 验证与边界

新增检查只覆盖关键新行为：真实权重的线性/二次梯度重建、取样不穿墙及退化拒绝；实际 GPU 均值修正的密度、速度和非平衡矩；几何迁移后的权重更新与采样缓存；一帧仅一次控制。复用已有测试及小型软件适配器诊断，不搭建新测试项目，不自动追加云端长测。

保持现有机械反馈测试的有效断言。均值修正会改变流体总质量和总动量，应单独记账，不伪装成细胞/机器人反冲量；已有单次 Guo 力矩检查不代表完整机械耦合验收。

此前实卡 p95 2.10 ms 是无机械的单窗口预算，且每帧只更新一次开口剖面。正式路径每机械子步 prepare，不能保证直接复现该预算。默认 small_world、开口穿分叉、近切向/欠分辨几何、完整游戏和绝对压力耦合仍保留已知限制。

物理说明独立保存为 [LBM 流体模型与算法](../../physics/lbm-fluid.md)，区分已选算法、实现状态、实验事实与尚未验证的范围。
