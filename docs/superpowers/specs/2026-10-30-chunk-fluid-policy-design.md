# 区块流体策略设计

2026-10-30。用户已确认“背景流场＋LBM许可”两层区块策略，并在本版审阅后回复“可以”，确认下文二维换算、驱动范围、预计算限制及交接取舍。**已按实施计划在feat/chunk-fluid-policy完成基础设施与软件功能回放，实际证据及未验收项见文末链接。** 心脏已确定暂不收缩、优先维持流动；器官几何和腔内流场生成方法另行细化，不由本文件默认选定。

## 目标与已有约束

地图作者在固定区块上声明基础流动与实时求解许可，提前排除不支持的LBM窗口；角色在不同区域移动时，始终有可用的基础流场。心脏可长期使用静态解析/预计算流，普通血管可在通过检查的位置启用LBM。

- 基础块16×16；一个LBM窗口覆盖3×3块即48×48，Fine为192²格；现场仍5×5块。负坐标向下取整，坐标使用已有ChunkId。
- 仍只有一个局部LBM窗口和一个Rapier世界。区块不各自拥有求解器，也不独立推进身体。
- 保留Rust、现有blood-fluid共享尺寸、可选lbm-gpu，以及现有MRT、LSQ-FD开口、均值控制与有限阻力耦合。不添加新依赖或求解器。
- 标签是地图的静态数据，不随显示块卸载而丢失。Godot背景缓存不参与流体决策。
- 本轮不包括心壁运动、真实瓣膜、双心室泵、气体交换、全图流体、磁盘流式加载、64×64实验、性能研究或云实验。

## 路线与取舍

| 路线 | 取舍 | 结论 |
| --- | --- | --- |
| 每块只选解析、预计算或LBM之一 | 写标签直观，但LBM未启用时缺少明确背景；容易误以为每块是独立求解域 | 不采用 |
| 背景流场＋LBM许可 | 每处都有基础流动，局部求解可独立启停；需要窗口检查和交接 | 用户已选择 |
| 首张大图全部解析 | 接入最简单，但无法表达作者选择的局部LBM区域 | 保留为关闭LBM时的运行方式 |

以下二维换算、首版预计算限制和交接方式是本次细化后经用户确认的决定。

## 地图数据

建议在MapDefinition增加可选的流体定义；旧地图无此定义时走原路径。定义包含默认策略、按ChunkId覆盖的稀疏表、被引用的静态场资产，以及下文的最大基础压差。默认策略为解析背景、禁止LBM；作者显式放开需要求解的区域。

概念模型如下，最终Rust命名由实施者确定：

```rust
ChunkFluidPolicy {
    background: Analytic | Precomputed(FieldId),
    allow_lbm: bool,
}
```

- Analytic在管道中使用抛物线速度剖面；不是新增PDE求解器。未来心腔的解析表达需有明确模型，不能自动当作一条宽管。
- Precomputed引用一个世界坐标中的区域流场。同一心腔跨多个块时引用同一FieldId，不按块分别烘焙、截断或拟合。
- allow_lbm表示该块**允许被求解窗口覆盖**，不是“角色在此块就启动”。固体块也不作隐式豁免，作者可成片设置覆盖许可。
- 默认值和覆盖项组成唯一权威策略；检查得到的有效窗口中心是运行期派生数据，不能作为第二份可编辑标签。
- 角色或实体跨块不会重建身份或软体。现有Aggregate/Hibernate含义不变。

首版继续由Rust内置地图构造定义这些数据，不引入JSON地图格式、编辑器、继承优先级或通用规则引擎。遍历显式许可块即可产生有限候选，不按整个空白世界面积枚举窗口。

## 背景场与统一流量口径

GraphNetwork/GraphFlow继续负责全局等效循环；不让不同区块独立决定流量。背景提供统一的世界坐标速度采样，供机器人、细胞、免疫移动、流向显示和LBM衔接使用。远场数量输运仍沿现有图边模型，不宣称支持腔室内部数量分布。

### 新策略地图统一二维换算

当前graph::sample_velocity使用圆管关系：平均速度Q/(πR²)、中心速度2Q/(πR²)。现有LBM开口使用深度D=1的二维关系：截面通量Q/D、中心速度3Q/(4RD)。二者不宜直接当作同一个背景场接缝。

建议仅在启用新区块流体定义的地图中，统一使用已有EQUIVALENT_DEPTH=1的二维口径：

```text
u(s,y) = tangent(s) × 3Q/(4RD) × (1 - y²/R²)
```

直管横截面积分应得到Q/D；解析端口、预计算端口、LBM开口均使用这一约定。近壁处理不能再额外把整个已归一化端口剖面乘衰减函数而不重新归一化。弯曲及分叉内的解析近似不据此宣称局部无散。

全局图仍沿用原等效阻力模型，不将二维显示/局部求解约定宣称为真实人体血流。旧默认地图、历史验证场和既有实验口径保持原行为，不借此次设计重写历史结果。若今后迁移旧入口，单独处理。

### 驱动适用范围

新地图的流体定义必须声明正且有限的`max_base_pressure`，允许基础压差范围为0至此值；没有隐含的Godot滑条上限。准备时以当前固定黏度建立图网络，并按`1.15 × max_base_pressure`计算最大瞬时驱动，覆盖现有±15%脉动。由这个上限生成参考流量/速度预算；各预计算资产也必须声明足以覆盖该范围的非负α适用区间。

创建与每个固定步开始、任何环境/实体/GPU状态推进前，验证Config.pressure有限且位于该基础范围；黏度、机械步长/子步与准备时一致。越界或改变这些准备条件时明确报错，要求调整回已允许范围，或修改地图声明后重建现场；不在运行中自动重新检查整图。Config.pulse_hz仍可改变，脉动幅度保持原15%；改变幅度属于准备契约变更。关闭LBM也仍遵守已声明的背景资产适用范围。

地图作者决定`max_base_pressure`的实际数值，后续大地图调参时确定，本设计不沿用撤回草案的33.261，也不把UI当前0～30当作物理边界。

### 预计算场的首版约束

本设计确定资产接口及采样契约，**不指定生成心腔流场的新算法**。首个真实心腔资产的生成方法、几何和端口定义仍须随后讨论。

- 资产包含世界坐标原点、正的网格间距、二维尺寸、参考速度场及流体掩码；相邻块通过同一资产采样，不复制切片。双线性插值需要的支持数据属于资产，不靠相邻显示块是否已加载。
- 资产声明所用地图几何版本、固定黏度、参考驱动及端口参考流量。几何版本由内置地图显式维护，不搭建自动哈希/资产构建平台。
- 当前静态单等效驱动、线性图网络下，可限定各端口流量比例不变，按共同系数u=αu_ref缩放。α由当前驱动相对参考驱动计算，所有端口同时核对该比例，不能各自缩放相互矛盾的局部片段。
- 首版限定参考驱动非零、比例α非负且在资产验证过的范围内。改变黏度、端口比例、驱动方向或几何需要重新准备资产；不增加多基底插值或自动在线重算。
- 资产覆盖标记为Precomputed的全部流体区域及插值支持；固体采样返回零。资产与解析背景只在显式直管端口连接，资产端口剖面使用同一二维约定；其他区域外围应是组织壁。不能在流体中任意换FieldId制造硬接缝。
- 资产与端口检查不通过时返回地图准备错误，不悄悄换成宽管解析流或零速度。
- 首版预计算区域禁止LBM；若作者把此类块显式标成允许，报告不支持的配置。现有LBM初始化/开口来自管道几何，暂不扩展为任意静态场边界。该限制不妨碍普通解析血管启用LBM。

## 候选窗口检查

检查发生在地图准备阶段，先于角色、软体推进及任何GPU窗口创建；不是运行失败后再猜测可否回退。只在显式请求LBM且编译启用lbm-gpu时检查LBM几何，不因普通解析运行引入GPU依赖。

对每个候选中心块c：

1. 取c及周围一圈的9块；缺省或任意一块禁止参与LBM，该中心不进入候选。由此心脏禁用区自然在可用中心集合外产生一圈排除范围，无需另一组手填禁区。
2. 首版9块的背景均须为解析管流。预计算许可的错误按上节报告。
3. 对实际请求的Fine/Coarse配置复用lbm_geometry的栅格化与开口检查：角点、歧义/近切向开口、直管缓冲、各流体连通分量是否具有可用开口等限制均保留。
4. 额外排除窗口覆盖等效泵段的情况：当前LBM没有域内泵压升，不能仅凭开口检查通过就批准。边界与泵段流体几何相交也不批准。
5. 使用地图声明最大基础压差的1.15倍，检查参考初场/开口速度是否在现有velocity_bound预算内；这只是输入预算，不是后续耦合速度的数值稳定证明。

输出一份有效中心集合，以及被排除的候选坐标/原因。许可标签覆盖不足可汇总显示；几何/泵段拒绝应定位到中心块。候选拒绝只令该位置保持背景流，整图仍可运行；预计算资产损坏等导致背景不可用的错误则阻止启动。

检查每个候选后只保存结果，不常驻所有192²栅格、不同时创建许多GPU窗口。候选检查与实际创建必须使用同一地图、profile和几何规则；改变这些设置或重置到新地图时重建集合。不引入磁盘检查缓存或运行中热编辑。

## 运行时选择与交接

### 单窗口的生命周期

显式启用LBM表示“在已批准中心启用局部求解”。没有请求LBM时全程采样背景；没有编译feature而请求LBM时仍明确报告不可用，不伪装成已启用。

每个固定模拟帧开始、任何机械子步之前，读取角色所在中心块并查询有效集合：

| 当前窗口 | 当前中心 | 动作 |
| --- | --- | --- |
| 无 | 无效 | 仅背景，不分配/推进LBM |
| 无 | 有效 | 从当前背景及图网络开口构造一个窗口 |
| 有 | 有效且相同 | 沿用窗口，更新开口驱动 |
| 有 | 有效且相邻 | 迁移16单位，复用现有重叠分布保留 |
| 有 | 无效 | 上一帧已finish；释放窗口，使用背景 |

新入口将“用户请求/配置”和“当前窗口Option”分开，否则从心脏出生时没有窗口便会丢失以后启用LBM的意图。不增加后台线程、窗口池、冻结GPU场、恢复队列或复杂通用状态机。退出区域后不保存涡旋，返回时从背景重新初始化。

整个固定帧锁定选定窗口及其原点；子步不因角色跨块而转向未经本帧准备的几何。下一帧再选择。该窗口始终是有效中心对应的合法几何，即使角色在帧末已跨边也不扩大它；窗口外继续使用背景。原有每帧末读回/密度控制完整结束，释放和迁移均不能发生在未finish的批次中。

显式重置或远距离重定位按新现场重建，不承诺跨不连续跳跃保留流体历史。旧独立LBM探针与固定负载实验不自动改为该选择机制。

### 推荐用空间权重交接

只在跨块时把权重从0跳到1，可能产生明显的速度变化。建议使用有效中心块并集的**外边界距离**，复用现有outer_band（默认4世界单位）计算启用系数：

```text
a = smoothstep(clamp(角色到有效中心区域外边界的内侧距离 / outer_band, 0, 1))
w = a × 现有窗口边缘混合权重
```

跨两个有效中心的内部块边界不降权；接近无效区域时才退向背景。有效中心外a=0。外边界由有效中心集合派生；实施者可采用简单边界线段距离，不需要距离场预计算或另一个调度网格。无效孔洞同样属于外边界。单块宽的有效区域也能在离边界4单位后达到完整权重。

同一个w同时用于背景拖曳的1-w、LBM对身体的作用及其反向marker冲量，机器人、红/白细胞和调试速度采样一致；不能只让箭头显示平滑。固体/无效样本的处理沿用现有契约，不把无效数据混入背景。首版不叠加时间淡入、额外预热计时或滞回状态。

该方案减少连续移动时的突变，不构成严格守恒或完全无感交接的证明。启停会丢弃局部流体状态，均值控制和空间混合也不是全图守恒算法；验收需要看真实速度与冲量的变化。高速度跳过过渡带或重定位属于显式重建边界，不虚构平滑保证。

LBM创建、推进、读回若发生GPU/求解错误，沿用现有明确报错方式，不自动重试或静默回退。几何候选未批准而只用背景是预先定义的正常分支，与求解错误不同。

## 模块职责与依赖

| 所在位置 | 职责 |
| --- | --- |
| map内的流体定义子模块 | 源标签、场引用、世界坐标和默认策略；不创建GPU或推进模拟 |
| simulation内背景场模块 | 解析/预计算采样、统一二维流量和资产校验；依赖地图与GraphFlow，不依赖Godot/Rapier句柄 |
| fluid的feature内检查/选择模块 | 候选中心、拒绝原因、空间交接权重；复用lbm_geometry，不复制几何判定 |
| runtime | 帧开始选择、单窗口生命周期、唯一身体推进、错误上报；各实体共用同一流体选择 |
| godot_bridge/Godot | 保持已有输入和显示；从模拟接收实际场信息，不维护自己的标签副本 |

这些职责在现有simulation crate内组织，不新增crate、服务或通用后端注册系统。核心不依赖Godot，默认feature不导入GPU实现。调试信息优先写入现有探针输出：当前中心、背景类型、候选拒绝原因、窗口有无、启用系数；不顺带增加HUD或地图编辑UI。

## 范围划分与验收

后续实施按三段组织，但本文件不是逐文件实施计划：

1. 标签与背景：新策略地图、二维管流口径、静态场引用/采样及准备校验。用短直管与小型真实资产夹具覆盖核心接口；不因此选定整张器官地图或构造心腔求解器。
2. 候选与交接：现有LBM验证场标注许可区/禁区，加入地图准备检查和单窗口启停；保持原机械、格子子步及均值控制。
3. 器官地图接入：在心腔几何、端口和场生成方法确认后，引用同一场资产跨块采样，心脏全部禁止LBM，选择普通血管片区放开。该段另有设计依赖，不把标签系统完成等同于大地图完成。

新增永久测试只覆盖关键新契约，并复用现有夹具：默认禁止及负坐标查表；窗口9块许可/现有坏开口/泵段排除；二维直管通量与端口一致；跨块共享资产采样/比例失配拒绝；真实模拟进入、离开、返回许可区。CPU检查覆盖不分配GPU时的选择结果，少量feature功能回放覆盖实际创建/释放，不机械复制各层断言。

相关已有检查按完整改动集中执行：`bash scripts/check.sh`、`cargo test --locked -p simulation --features lbm-gpu`、`cargo check --locked --workspace --all-targets --features godot_bridge/lbm-gpu`。新增启停回放使用已有探针，软件GPU可作功能证据，不作为实卡性能或物理精度结论。UI验证最多截图，不自动键鼠操作；不新增云实验、端到端平台或profiling。

实际混合场仍需检查无墙面明显穿透、端口方向与速度连接、身体不被重复施力、禁区从不创建/迁入窗口、返回时数量及身份策略不变。宽心腔数量分布、完整游戏手感、任意复杂端口、实卡FPS和长程稳定性均未由本设计验收。

## 本版审阅后确认的具体决定

1. 新策略地图采用二维等效深度口径，旧入口保留原行为。
2. 地图声明最大基础压差，计入15%脉动进行准备；首版预计算场只支持固定端口流量比例的共同缩放，且不参与LBM。
3. LBM按固定帧选择单窗口，退出释放、返回重建；复用现有4单位宽度做空间交接，不保留离场流体历史。

独立只读builder检查仅提出驱动上限及调压越界处理需明确，已按“地图声明上限、运行前检查、越界报错”补全；无其他影响制定计划的问题。用户随后确认本版设计。
