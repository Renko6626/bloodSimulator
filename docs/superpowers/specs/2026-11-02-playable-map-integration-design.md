# 候选A实装接入方案

用户已确认城市式平面路网方向，并接受当前跨区尺度和远处约2～4分钟的理想步行估算。空间基线为[候选A](2026-11-02-playable-vessel-network-design.md)。2026-11-02用户以“开干”确认本文件的接入接口与验收范围，开始执行；后续结果另行记录。

## 推荐边界

本轮把候选A落成实际几何、碰撞和区块加载，提供可走图的独立零流/零细胞预览。旧对称地图继续通过`--heart-preview`使用；新地图新增`--organ-preview`。普通游戏、`--stream-world`小地图、Local/LBM及旧探针入口保持原样。

这使两张地图可分别维护和比较，代价是增加一个明确入口及很小的双预览模式选择。直接替换旧入口会混淆已归档验证；将新地图直接放进带细胞/血流的普通场景，则超出了尚未接好的心腔流场和数量分布范围。

## 具体接口

- 地图：`MapDefinition::organ_world() -> Self`，私有`map/organ.rs`保存候选A的固定道路数据与少量构造辅助；不从研究Python脚本或新JSON格式动态加载。
- 运行：`Simulation::new_organ_preview(Config) -> Self`；保留`new_heart_preview`，增加共用`is_geometry_preview() -> bool`。旧`is_heart_preview()`仍仅表示旧心脏验证场。
- 内部用一个只含旧Heart/新Organ的私有预览类型替换单个heart_preview布尔值，确保reset回到原地图，暂停状态保留；这不是通用场景注册或状态机框架。所有非预览构造仍无预览类型。
- 桥接：`BloodLab::use_organ_preview()`；两种预览的参数入口、step/reset都固定pressure/pulse/红白细胞为0。
- Godot：新增`--organ-preview`，隐式stream/zoom2，HUD清楚显示新地图及无流/无细胞。与`--heart-preview`互斥；沿用预览对LBM/Stokes/profile/benchmark的拒绝规则，speed/WASD/暂停/单步/重置/碰撞显示保留，压力、拖曳和流向/F禁用。
- 静态工具：`map_render --map organ`选择新图；默认heart和既有small-world不改，不新增区域名预设。

## 几何落地

以草图32条外部道路、已标路口及平移(+450,+650)后的真实四腔为基线，保留两套串联网络、区域绕行和两条3单位窄联络。A/B/C阴影不变成新增流体房间；它们只作区域/入口认路标记，不新增任务或实体布置层。

只把有意路口、端点和宽度接续点作为图节点，普通折线转角留在VesselEdge.centerline；共享路口必须真正拆边，不能让SDF相接而图边未连。图中无跨层，宽管端帽和原心腔之间也要检查，不只看中心线。

两张地图共用四腔原始轮廓的小型私有函数，旧地图坐标、窄管和等长补偿模板保持。其他道路属于各图内容，不顺带重构成通用生成器。现有定宽VesselEdge继续使用；端口接近采用短定宽分段及现有圆角胶囊并集，不引入连续半径函数。允许为净空和转弯作局部点位修正，不能为了缩短赶路改整体分区、删环路或缩小心室。

肺下口双路近路先按图保留，A/B/C以当前占位落点实装，不据此确定新器官身份。若实际几何无法在现有模型中保留这些关系，报告具体冲突；不以虚拟边、阀门、局部限速、假立交或新模型掩盖。

## 图流量与运行流场的区别

生产GraphNetwork用默认黏度在单位全局驱动下求解，输出各段真实比值、节点守恒、正反/低流量及肺下口分流情况，给后续校准提供依据。**本轮不指定新的最终Q/压差，不强制所有同径支路等流，也不把单位驱动数据接入游戏。** 旧Q48、旧预计算资产与烘焙方域不复用。

心腔离线烘焙、实际背景采样、细胞面积分布、设备/任务/病原体内容、移动加速或传送均不在本轮；性能和云实验继续暂停。

## 有限验证

- 少量真实地图测试覆盖有意路口、单图连通、双外网隔离、宽管/心腔无额外开口、典型通道和统一图求解；不穷举所有游玩路径。
- 导航先做便宜的连续路段SDF净空检查，再做实际MoveInput检查，发生不足立即报告位置，不等整次回放末尾才失败。
- 正常出生点短程路线覆盖心室/肺中央路口/一条窄联络；体侧关键路口及另一窄联络可用明确记录起点的局部独立初始化案例验证，不瞬移运行中的身体，也不把局部结果当作全图出生点可达证明。
- 显式诊断例子承担这些回放，不把长路线放入默认测试套件。不要求重跑旧211点全图，也不为本轮新图另做数十分钟完整巡游。
- 末尾集中跑默认项目检查、feature测试和all-target feature编译；Godot只加载和静态截图，不自动交互。局部修正只补受影响项。
