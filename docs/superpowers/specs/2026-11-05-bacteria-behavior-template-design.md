# 基础细菌行为模板

日期：2026-11-05。状态：用户已确认并要求开工；已在 `feat/bacteria-behavior` 实现，集中检查与独立代码审阅通过。人工手感与FPS未验收，详见同日实施计划及阶段记录。

## 目的与已确认方向

先把现有细菌的基本行为做完整，让玩家看到它主动寻找正常细胞并造成损伤，能够介入清除，也会面对细菌的自卫反应。后续不同细菌可复用这套基础过程，再添加各自需要的特征。

用户已确认：

- 基础细菌主动寻找正常细胞并造成伤害。
- 受到攻击后反击或逃离，由病原体配置决定，两种能力都保留。
- 反击对机器人同样有效；平时不会主动把机器人作为猎物。
- 细菌独立决策，共用现有移动、碰撞和伤害处理。
- 本轮先完成行为模板，沿用现有外观、生命与攻击数值；繁殖、感染另行设计。

本文中的默认配置、逃离余时及细节规则是本稿建议，随整份设计确认后采用。这里的基础细菌是游戏原型，不代表所有真实细菌的行为。

## 现状与影响范围

`Species` 已区分红细胞、中性粒细胞、巨噬细胞、游动细菌、荚膜细菌。`Behavior::Immune` 与 `Behavior::Bacterium` 目前都持有 `WhiteCell`，由 `runtime/immunity.rs` 混合处理目标选择、受击、移动和接触攻击。

现有细菌感知半径为 4，需要墙体视线通畅；优先反击攻击自己的免疫细胞，否则保持当前红细胞目标，再选最近红细胞。对机器人攻击没有自卫反应。移动沿用有限转向、三方向近身避墙、软体碰撞和血流叠加。

普通世界继续保留现有种群；细菌仍从 `--combat-preview` 观察。器官地图种群、流体路线、机器人攻击能力、免疫通缉与增援规则均沿用现状。

## 方案与取舍

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 在共用白细胞行为里继续加分支 | 初始改动少 | 细菌逃离与免疫追捕、调查和呼叫继续耦合 |
| 细菌独立决策，复用移动与伤害处理 | 行为归属清楚，后续增加细菌特征时影响集中 | 需要局部整理共用运动与接触攻击状态，以及读取它们的位置 |

用户已选择第二种。不引入 ECS、行为树、事件总线、通用能力注册或新依赖。

## 配置

在现有 Rust `Config` 中增加细菌配置，按游动细菌、荚膜细菌分别设置受击反应：`Retaliate`（反击）或 `Flee`（逃离）。同种个体使用同一配置，不做个体覆盖、概率抽签、血量阈值或自动变换性格。

建议两种细菌默认都用 `Retaliate`，保留已有反击性格；使用 `Flee` 的配置通过构造 `Config` 传入现有模拟入口即可。第一轮不增加命令行开关、配置文件或游戏设置面板。reset 保留传入的细菌配置。

逃离速度沿用该物种现有追近速度，感知半径仍为 4。新增一个按种类设置的逃离余时，建议默认 0.8 模拟秒，表示失去威胁感知后继续沿最后逃离方向运动的时间。已有速度、转向时间、接触准备、伤害和攻击间隔保持数值不变；不要求把所有现有数值迁移成一套新配置系统。

荚膜细菌受到免疫接触攻击时的 0.5 伤害倍率保留，机器人攻击不受此倍率影响。低速荚膜细菌选择逃离时仍然缓慢，不承诺能摆脱免疫细胞。

## 基础活动与寻找目标

1. 无目标时随血流运动，叠加原有主动游动与周期转向。
2. 仅在活动、存活、半径 4 内且墙体视线通畅的红细胞中选择目标。保持仍然有效的当前目标；没有目标时选择最近者，等距按稳定实体 ID 决定。
3. 有目标时主动追近，由实际轮廓接触与墙体遮挡决定是否可以准备攻击。
4. 连续接触达到该物种准备时间且冷却结束后，造成一次伤害。接触中断或攻击目标改变时清空准备进度，冷却不会因此缩短。
5. 红细胞死亡、休眠、移出感知或被墙遮挡后，立即放弃对其追踪；可选择新的可感知红细胞，否则恢复游动。不读取失去感知后的坐标，也不向旧位置调查。

主动捕猎与自卫使用相同的接触伤害规则。细菌不伤害同类，不仅因免疫细胞或机器人靠近就进入自卫。

## 受击与自卫

触发需要细菌实际受到正值伤害且存活，来源为机器人或免疫细胞。目击其他细菌受击不触发协同反击或逃离。

一次伤害处理批次存在多个直接攻击者时，沿用当前规则选伤害较大者，平局按稳定来源 ID 决定。新一批有效受击可替换当前威胁；不增加多威胁列表、累计仇恨或攻击者排名系统。受击事件只提供来源当时的位置；后续位置更新仍要满足正常感知。

### 反击配置

- 直接攻击者仍存活、活动且可感知时，优先攻击它，暂时放弃红细胞目标。机器人和免疫细胞适用同一规则。
- 攻击者死亡、休眠或不可感知时，清除这次自卫记录，恢复基础寻找；后续再次靠近不会自动恢复旧仇恨。
- 若受击时攻击者已不在感知范围内，不追向受击来源旧位置。
- 反击结束或改变攻击对象时，清空接触准备。继续正常推进攻击冷却。

### 逃离配置

- 受到有效攻击时，取消攻击目标并清空接触准备，以远离攻击来源的方向作为运动意图。
- 威胁仍然可感知时，持续依据可感知位置更新逃离方向。逃离期间不寻找红细胞、不准备攻击，也不因碰撞而自动反击。
- 失去威胁感知后，仅保留最后逃离方向，持续配置的余时；期间不更新隐藏威胁坐标。同一威胁重新进入感知时可恢复实时逃离。
- 若受击来源一开始就不可感知，使用事件中的来源位置确定一次逃离方向，然后执行余时。
- 威胁死亡、被删除或休眠时，结束对其实时追踪并执行同样的余时。余时结束清除威胁身份，恢复基础寻找。
- 再次受击按新的直接来源更新威胁和逃离方向。不存在新伤害时，不会因看见其他免疫细胞而更换威胁。
- 方向为零时沿当前朝向推进。局部避墙继续生效；无可用方向时允许停止主动推进并转向，不加寻路或脱困流程。

逃离状态仅为这项已请求行为所需的威胁引用、最后方向与余时。不加入恐惧值、警戒传播或其他恢复机制。

## 模块职责与依赖

- `pathogen.rs`：拥有细菌专属状态、受击反应配置与决策。输入由运行期准备的局部可感知对象及直接受击信息；输出运动意图与可攻击目标。它不查询或修改 Godot、地图、流体和其他实体生命。
- `white_cell.rs`：保留免疫细胞的巡游、调查、追逐、通缉识别和呼叫状态；细菌不再持有完整 `WhiteCell`。
- 共用简单记录及函数：仅收敛两类行为实际共用的朝向/运动意图、有限转向与接触准备/冷却等。免疫记忆、呼叫和入场计时留在免疫行为；威胁和逃离余时留在细菌行为。共用记录不反向调用两类决策。
- `runtime`：从同一个物理世界准备活动对象、范围/遮挡判断及受击事实，分别调用两类决策，再复用现有局部避墙、流体叠加、身体驱动及统一伤害结算。细菌决策与免疫决策不能互相调用。
- `combat.rs`：继续负责真实轮廓接触、遮挡与伤害语义。攻击动作必须显式具备可攻击目标；逃离的威胁引用不能被当成攻击目标。
- `cell.rs` 与休眠逻辑：继续持有行为枚举和物种，保存细菌状态。休眠时 AI 和行为计时冻结，恢复时清空接触准备并重新验证威胁/目标；不借休眠获得隐藏目标的实时位置。

保留现有 `Behavior` 枚举，通过明确的分支或小型访问方法读取共用输出，不用返回虚构的 `WhiteCell` 保持旧访问接口。现有受击批次、相互致死结算和机器人被击杀后的停场顺序不变。

具体共享记录名称、所在文件以及短函数拆分留给实施者，限于以上职责，不新增 crate 或改变外部架构。

## 显示与生命周期

沿用现有细胞外观、接触准备提示和伤害反馈。`CellStatus` / Godot bridge 字段保持现状：

- `target_position` 与 `targets_robot` 对细菌只描述正在攻击或追近的目标；逃离时分别为 `None` 和 `false`。
- 逃离时 `contact_progress` 为 0，不显示朝向威胁的攻击准备弧。
- 细菌的 `call_progress` 为 0，入场透明度沿用现有实际效果；免疫呼叫与入场提示保持原行为。

本轮通过实际移动表现逃离，不新增图标、粒子或姿态动画。现有低速物种的逃离可能不明显，人工试玩后再判断是否需要表现或数值调整。

死亡立即停止决策与主动攻击，继续现有变软、随流及尸体清理。暂停、单步、reset 和休眠均使用现有模拟时钟和规则；reset 清空临时目标与威胁，并保留场景及配置。

## 范围与验收

不增加繁殖、宿主感染、毒素场、黏附、生物膜、完整吞噬、远程攻击、新种类、种群投放或性能实验。此次整理不能改变免疫细胞行为或自动重做美术。

实施阶段优先复用 `runtime/immunity_tests.rs` 的真实模拟夹具，在最合适的一层覆盖关键新增行为：

- 基础细菌主动损伤红细胞，未受攻击时不主动攻击机器人。
- 反击配置下，对机器人和免疫直接攻击者都能造成接触伤害；失去感知后结束自卫，旧攻击者重新出现不会无故重获优先权。
- 逃离配置下，出现远离威胁的主动运动且不造成接触伤害；失去感知只使用最后方向，余时后恢复寻找红细胞。
- 逃离切换清空接触准备、冷却继续；reset/休眠恢复与显示输出不会把威胁误当攻击目标。根据已有覆盖补缺，不机械为每种组合新增用例。

保留并运行相关免疫、战斗、休眠与快照检查；不得删掉旧有效断言掩盖行为回归，旧“细菌不反击机器人”的预期应按本设计更新。

完成全部改动后集中执行项目要求的格式、编译、模拟测试、桥构建与场景加载检查；依据实际修改范围选择已有命令，不重复长回放或已归档性能验证。Godot/UI 验证最多静态截图，不自动点击、按键或操作流程。测试结果、实际命令与人工手感未验证项在交付记录中分开报告。

本设计阶段只写文档并审阅，不运行产品测试或启动引擎。
