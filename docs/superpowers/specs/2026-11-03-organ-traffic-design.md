# 新地图可信交通：心脏背景场先行

日期：2026-11-03。状态：用户已选择A，要求先烘焙心脏附近区域，离开指定区块后使用解析流。本文件细化第一阶段的覆盖、接口和验收，用户随后回复“我觉得可以，开干”确认本版。已开始实施；实际预检和首次中断见本阶段research记录。

## 目标与阶段顺序

在当前候选A器官地图上，先打通真实心腔的离线流场与外围解析血管，再接细胞交通。保留现有路网、四腔大小、24/12/6/3管径、16单位块、5×5现场、单Rapier世界和全局等效图驱动。

1. 本阶段：确定心脏背景区域、四个直管交接端口及参考驱动，完成有界烘焙、资产导入和运行采样。先不加入细胞，避免把几何、流场和交通问题混在一起。
2. 后续同会话工作：在已可用的背景上确定细胞密度与初始分布、接入红白细胞、修正新策略地图的远场速度口径，并检查代表性交通。具体密度和实现计划另行细化，不因本文件自动选择新的心腔远场模型。

最终交通按用户选择的A：近处为真实二维几何内的软体与碰撞，远处仍按图边数量输运。远场不保留普通红细胞身份、心腔二维分布或精确停留时间。

## 既定路线和本次选择

- 沿用已确认的背景场＋LBM覆盖许可架构，以及现有离线LBM固定域、时间平均、BFLOW001资产和生产背景校验。
- 本阶段运行时仅用背景：心脏附近为预计算场，外围为二维解析管流。所有区块禁止实时LBM，不增加运行时GPU依赖。
- 继续一个全局等效泵，不模拟收缩、动态瓣膜、双心室泵、绝对生理压力或气体交换。

本轮讨论过两种细胞路线：A沿用图边远场库存，改动集中在背景接入与眼前交通；B增加心腔远场空间分布，需要新的区域库存和输运交接。用户选择A，并要求先做好心脏烘焙。离线生成与实时运行分开：生成可以使用现有GPU模块，导入后的背景由CPU采样。

## 离线域与生成

使用一个固定正方形域，覆盖上述标签区域中所有流体和插值支持；原点、边长由生产几何的CPU预检确定。求解域允许比标签区域大，域外边界上的开口与运行时四个交接截面是两套不同位置：域边界留求解缓冲，运行端口在资产内部取样。

- 首选格距h=0.5；四个D24交接截面有48个网格间隔，不改变原端口精度要求。
- 先检查完整域内的真实几何、所有边界开口、连通分量和各分量开口通量收支，不创建GPU。域若包含额外外围血管，应明确记录其开口和分量；不要把它们误计为心腔入口。
- 域内SDF使用真实四腔与管道并集；心腔引导边只用于图流量和初始场，不能作为心室墙体或最终流场。
- 继续使用既有D2Q9 MRT、Guo、LSQ-FD开口、帧末均值密度控制和时间平均作业，不添加新的PDE、质量控制或自动收敛机制。
- 保留原始格心资产，按现有生产双线性重采样流程生成地图对齐资产；不能用手工速度、逐端口归一化或放宽校验替代求解结果。

在CPU预检和离散参数确认后执行一次明确预算的本地作业。作业说明先列出格点规模、dt、预热/采样时长、读回间隔、样本数和最长墙钟时间；超时或失败保留报告并停止，不自动加倍预算反复烘焙。预算与必要修订属于随后实现计划中的具体作业安排。

软件适配器仅作明确标注的功能/资产生成作业，不作为实卡性能结论。没有云实例授权，不启动Vast.ai，不运行已暂停的性能研究。若本地预算不足以得到可用资产，报告实际障碍，再讨论新的作业安排。

本机只读设备检查显示`nvidia-smi`无设备，且不存在`/dev/dri`，因此计划按本地软件适配器估算，不默认有硬件GPU可用。

## 全局驱动与速度口径

所有端口参考流量来自生产GraphNetwork，继续使用黏度0.05。外围管流、资产端口和后续新地图的远场输运统一使用共同深度H=1的二维口径；旧地图和旧实验保持原行为。

建议以串联循环Q=48作为首个烘焙参考工况，而不是复用旧地图压差。当前归档单位图的泵Q约3.393265724，故参考压差估算约14.145665，实施时从生产求解重新获得。

此选择让承担全流量的D24直段均速为2；D9/10心口均速约5.33/4.8，部分D12支管可到4，两个D3联络非常慢。新路网已放开固定均流模板，不能承诺全图同时落入旧速度目标表，也不逐边限速、删近路或修改图阻力模型。

初版最大基础压差取参考压差，允许0至该值；运行时保留既有±15%脉动，资产声明覆盖0..1.15的共同速度缩放。该缩放是已接受的玩法近似，时间平均场不表达脉动引起的流型变化。参考驱动仍须在实际烘焙中通过速度、密度和端口检查；若必须改变参考Q或适用范围，记录原因后再确认。

- 原始`MapDefinition::organ_world()`继续提供同一几何；运行构造加载单份资产并装配现有MapFluidDefinition，通过`try_new_policy_world`的正常校验。资产缺失或不匹配时报错，不能退回窄管引导流或零场。

## 验收和停止条件

本阶段以可用背景资产为交付门槛：

1. 生产几何CPU检查通过；运行来源只有四个声明直管交接，心腔没有被区块边界截断为解析区。
2. 真实有界作业完成，保存输入参数、源码与资产来源、样本数、密度范围、各开口通量、前后半均值变化和实际用时。有限状态或样本均值接近不自动等于收敛或物理精度证明。
3. 资产实际读回，经原有掩码、几何版本、共同流量、端口剖面、支持范围和最大驱动校验通过。
4. 四个来源接缝内外采样方向、速度和通量可对照；检查心腔壁附近法向速度、主通行区域是否有明显穿壁或大面积意外零场，并保留流线/速度静态图。壁面格点置零不能单独证明壁面法向流正确。
5. 新入口在关闭GPU feature下能加载背景，完成有限的心腔进出和跨来源边界检查，暂停/单步/reset语义正确；Godot只加载与截图，不自动键鼠交互。

新增永久测试只补关键新行为：真实资产正常导入、新入口/reset及新策略地图必要的口径契约。复用现有背景/端口和例子测试，不为每张静态图写重复断言。

末尾集中运行相关默认检查、feature测试和all-target feature编译；具体命令及实际结果记入阶段报告。局部修订只补受影响检查，不重跑旧长路线或全部硬件实验。

本阶段不据零细胞背景验收声称细胞通行、全图交通、手感、稳定FPS或心腔物理精度已通过。背景可用后再开始第二阶段的细胞密度与交通接入。
