# 固定区块、模拟范围与实体卸载设计

2026-10-30。用户已确认固定16单位世界网格、LBM为3×3区块、地图与实体为5×5区块，并明确安排实装和缩小摄像机视野。本版取代此前32单位区块、独立72/80及96/128加载范围的草案。

## 范围和职责

| 内容 | 契约 |
| --- | --- |
| 基础区块 | 世界原点锚定的16×16网格，负坐标向下取整 |
| LBM | 玩家所在块及周围一圈，3×3＝48×48；Fine仍192×192格，迁移16单位 |
| 现场 | 玩家所在块及周围两圈，5×5＝80×80；玩家在同块移动不改变范围 |
| 边界身体 | 完整AABB离开现场才卸载；跨边缘的活跃身体所需墙块暂时保留 |
| 摄像机 | 新流式入口zoom=2，1280×800下约26.7×16.7世界单位；旧入口不变 |

共享基础尺寸定义在现有blood-fluid crate，simulation地图网格和fluid-gpu窗口均引用它，不新增公共基础crate。现场半径为2块；不另设7×7保留环或玩家中心连续移动的加载矩形。

全局MapDefinition、GraphNetwork/GraphFlow、红细胞数量库存仍在内存。附近区块生成显示/碰撞几何；一个Rapier世界推进所有活跃身体。地图和实体的归属使用同一固定网格；跨块不更换身份或重新创建仍活跃的身体。

## 地图装卸

- 显式`--stream-world`启用，默认旧世界与`--local-cells`路径保留；loop lab与local Stokes组合拒绝。
- 流式构造不生成全图MapGeometry。每块核心80×80个0.2单位采样单元，使用全局整数采样坐标和已有marching-squares、权威SDF。
- 核心单元按固定网格唯一归属，不在块边封口。显示另采样两格留边，核心碰撞与带留边绘图分别保存；这是两份局部派生几何，不是全图缓存。
- 基础现场加载25块；接触现场边界的真实身体可能暂时需要额外墙块，不能为硬凑25删除身体仍需的墙。实体完全离场后释放。
- 墙发生变化时复用Rapier detect_collisions刷新查询，AI前完成；不增加模拟时间。
- Godot通过新增/移除增量接收静态几何，每块384×384核心像素，四边8像素留边，Sprite仅显示核心。地标背景、框和文字按实际绘制范围跨块裁切。
- 空块不分配背景纹理；卸载销毁Sprite、SubViewport、Painter与资源引用。正常帧不重新传整图几何、不重烘焙。

LBM从常驻地图定义生成自己的固体格子和开口，不读取背景纹理或Rapier墙。区块卸载不改变血管定义、不重置流体。当前3×3窗口及迁移目标由5×5基础现场覆盖；既有开口限制保持。

## 实体策略

Cell保留一份身份、生物和行为记录，身体只有`Active(SoftBodyHandle)`或`Dormant(DormantBody)`两种互斥表示；Dormant只保存粒子位置/速度，不保留失效句柄或第二份权威位置。

- **Aggregate红细胞**：完整身体离场后回一份远场库存并删除身体/个体；尸体直接清理扣总量，不回活库存。沿用0.2模拟秒和按血管弧长区间的输运模型。
- 库存分区中心对齐玩家所在块中心，详细范围半边长由5×5推导为40；仅跨块重分区。运行期构造检查实际镜头，画面内不补填。
- **Hibernate白细胞**：离场保存形态并删除真实身体；休眠期间不移动、感知、攻击、呼叫，AI记忆及局部冷却冻结。全局警觉、共享呼叫冷却及红细胞输运继续。
- 尸体寿命是例外：休眠也继续计龄，6模拟秒到期删除；全局暂停冻结计时。休眠白细胞及未到期尸体计入原8只上限。
- 返回5×5现场后，在实际镜头外尝试恢复原位置/形态；拥堵时保留原记录以后重试，不移位、不换id、不补血、不增加请求队列。初始化允许画面内创建；拥堵持续至可见区域时本次经过可能暂不出现。
- 恢复通过原类型圆盘建立静止约束，再设置保存位置/速度及尸体材质/目标面积，避免把变形轮廓当作新静止形状。
- 仅支持当前固定节点、无撕裂身体；未来Boss专有状态与身体另行设计，不预建ECS。

动态snapshot只包含活跃轮廓和同序元数据，休眠记录不参与AI/机械/marker耦合。reset清理库存、休眠及块资源，保留模式、地图和原种群选择。

## 实施和验证边界

按几何→身体表示→Rust交接→Godot增量背景→LBM验证场顺序接入。旧Full/Local及固定负载实验保留，原机械/流体参数不改。新增少量真实行为用例，复用数量、免疫与尸体测试；UI只截图，不做自动键鼠交互。

有限规模检查使用300/1000/3000单位稀疏闭合地图，仅验证地图资源随局部范围装卸；零细胞回放不作为完整游戏性能证据。完整负载另用原72细胞LBM验证场做软件GPU功能短测。

仍保留全图初始化候选生成、速度/SDF查询、图求解等成本；不据此宣称数千节点或高密度大地图达到目标帧率。多线程加载队列、空间索引、磁盘存档、远处个体移动、复杂票据及新的GPU优化均不在本轮。

[64×64 LBM候选实验](../../research/2026-10-30-lbm-64-window-draft.md)仅记录草案，不实施、不启动云实例。当前实装仍为48×48。
