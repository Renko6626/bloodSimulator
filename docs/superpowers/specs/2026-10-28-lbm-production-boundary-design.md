# LBM 生产边界提案

日期：2026-10-28。状态：用户已确认。

## 推荐决定

在现有 `blood-fluid-gpu`（`crates/fluid-gpu`）中增加独立的 `lbm` 模块，拥有 LBM 的普通契约类型及后续 GPU 实现。`simulation` 通过可选的 `lbm-gpu` feature 依赖该 crate；默认 features 为空，现有默认构建与 Stokes 路径保持原样。显式启用该 feature 才编译并接入 LBM；不自动替换现有局部流体。Cargo 依赖方向为 `simulation → blood-fluid-gpu → blood-fluid`，并保留现有 `simulation → blood-fluid`。研究目录仅作为移植和验证参考，绝不成为生产 path dependency。

现有 `blood-fluid-gpu` 的 crate 文档写着“never a simulation dependency”。本决定明确修改这一旧约束：仅 LBM 的可选生产模块可由 simulation 使用；现有 Stokes factory、实现及所有权不变，也不把 Stokes 调优重新纳入本任务。尽管 Cargo 会编译同 crate 的现有代码，这不表示 simulation 调用 Stokes GPU 后端。

备选是新建 `blood-fluid-lbm-gpu` crate：LBM 与 Stokes 的依赖及发布边界更清晰，也保留旧 crate 的原表述；代价是增加 workspace 包和 GPU 初始化代码的独立维护。眼下两者使用同一 wgpu 版本且 LBM 接口可由模块隔离，推荐扩展已有 crate，避免为首次接入增加 crate。若以后依赖或维护生命周期确实分离，可再讨论拆分。

## 最小契约与单位

以下类型均由 `blood-fluid-gpu::lbm` 拥有，使用普通 Rust 数值和数组，不暴露 `wgpu`、Rapier 或研究代码类型。数值字段建议 `f32`，区块坐标用有符号整数；接口契约优先于具体内存布局。

- `GridProfile::{Fine, Coarse}`：固定窗口 48×48 世界单位；每单位分别 4 / 2 格，192×192 / 96×96，格距 0.25 / 0.5 世界单位。16 单位一个逻辑区块，移动一个区块分别为 64 / 32 格。
- `WindowOrigin { block_x, block_y }`：窗口左下角的整数区块坐标，世界原点为坐标乘 16；二维世界坐标遵循地图坐标轴，格索引以该原点为基准。`WindowSpec { origin, profile }` 导出尺寸、格距及世界范围；profile 在创建或重置时选择。
- `OpeningSpec`：边界侧（左、右、下、上）、该侧连续开口格的半开区间 `[start, end)`、指向管段的世界空间单位方向、有符号目标流量和背景速度尺度。流量以世界单位²/游戏时间表示，沿边界外法线向外为正；速度以世界单位/游戏时间表示。开口和固体掩码由 simulation 从地图及网络提供，开口目标随网络状态更新。必要的剖面值按格中心由调用方提供或依据目标流量归一化；不得将每步整个开口强制重置为解析场。无法提供稳定直管缓冲时返回可观察错误。
- `FluidSample`：局部速度与解析背景速度（世界单位/游戏时间）、局部混合权重 `[0,1]`、局部状态（有效、窗口外、固体/无效）。地图几何确认窗口外采样点属于流体时，局部权重为零，使用解析背景速度；窗口内有效流体位置按权重混合。固体或无效位置不施加墙外背景流；局部反馈同权重缩放。解析采样、混合权重和实体/ Rapier 状态由 simulation 负责，GPU 后端只提供局部场结果及有效性；simulation 组合为该契约。

网格中心位于 `origin_world + (index + 0.5) * h`。后端内部保存 LBM 步长 `dt`（游戏时间）、无量纲密度和 lattice 速度；世界速度换算 `u_world = u_lattice * h / dt`，反向 `u_lattice = u_world * dt / h`。参数选择及稳定性由后续数值验证确定，不在契约中假定具体时间步或质量单位。

## 后续调用边界与故障策略

后续以窄接口提供创建窗口（spec、掩码、开口与初始化背景）、更新开口、推进固定步及局部作用力、读取世界坐标采样/诊断、按区块迁移并重用重叠状态。具体批量数据形状随实际调用确定，避免先建立通用求解器框架。simulation 管理地图、全局网络、窗口调度、混合和 Rapier；后端管理 GPU 资源、分布函数和数值步骤。API 返回普通值和明确错误，不向 simulation 暴露 wgpu 对象。

默认只接受硬件 GPU；找不到适配器、设备创建失败或只找到软件适配器时，创建 LBM 返回错误，调用方报告不可用，不静默选择软件或声称 LBM 已运行。软件适配器仅通过显式诊断选项允许作功能检查，结果标记软件设备，不能用于游戏性能结论。是否提供游戏层解析背景降级及其用户体验留待接入时明确，不在此假定自动切换。`lbm-gpu` 关闭时现有模拟行为不变。

## 开口重建：数值方案和验证

已有动态窗口设计要求在实现前固定具体重建；此处推荐将其视为已确认架构下的数值离散选择，而非新增模块边界。采用 D2Q9 Zou–He 速度边界的未知入射分布重建：先由已知出射和切向分布及给定法向速度解密度，再以对向非平衡部分回弹关系重建入射分布，并由切向动量约束确定对角项；四边通过旋转方向处理。按开口剖面离散积分归一化，使目标法向通量匹配网络流量。注意研究实现存储 `g_i = f_i - w_i`，且 Guo 力下动量为 `ρu = Σ c_i f_i + F/2`：重建前后必须一致处理偏移及半步力；禁止直接套用无力公式而忽略修正。参考 Zou & He, *Physics of Fluids* 9, 1591–1598 (1997), https://doi.org/10.1063/1.869307 。

先用无力直管验证方向、积分流量及密度漂移，再用零扰动平衡验证不产生伪流，并用分叉检查各开口流量、质量收支和中心区瞬态；另针对 Guo 力检查速度和动量一致性。如果这种速度边界无法同时维持质量稳定与多开口目标流量，应报告结果并另行确定质量修正，而非悄然增加恢复机制或更改全局流量权威。现有研究 shader 的 x 方向周期回绕和可选 y 周期边界不可直接用于窗口开口。
