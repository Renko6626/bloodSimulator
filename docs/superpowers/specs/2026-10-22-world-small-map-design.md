## 算法候选与推荐

### 地图几何

推荐“中心线图与管宽定义通道，静态采样管道并集并提取边界”。每个图节点有稳定 ID 与坐标，每条边引用端点 ID，并给出中间路径点、半宽与稳定边 ID。边的首尾坐标从节点取得，避免各处分别维护连接点。

对各折线段计算点到线段的距离减去管道半宽，取最小值得到通道并集的隐式函数；初始化时使用 marching squares 提取零等值边界。碰撞墙、地面填充和墙面绘制使用同一份离散几何。先合并通道再提取边界，分岔口不会保留两条独立管道的内部墙。

| 选择 | 优点 | 代价 | 本批建议 |
| --- | --- | --- | --- |
| 隐式并集与 marching squares | 不需新依赖；分岔、汇流和不同管宽统一处理 | 离散分辨率影响轮廓；需要一次性边界生成 | 推荐 |
| 带宽多边形的布尔并集 | 可直接得到矢量边界 | 现有依赖未发现可直接用的并集入口；需新库或更多几何代码 | 暂缓 |
| 手写分岔模板拼接 | 一张固定小图可较快制作 | 增加交汇角和管宽后，接口拼接维护成本上升 | 不作为主方案 |

首版以 0.2 模拟单位作为网格步长的试验起点，按现有细胞半径 0.7、机器人半径 0.85 和墙厚检查轮廓。静态生成结束后运行时使用生成的边界，不在每帧重建。鞍形格子的连接使用同一套明确判定，地面与墙体不能各自选择拓扑。具体轮廓连接和三角化组织由实施者确定，但必须共享边界交点。

小图使用明确连接的平面路线，几何交叉只能发生在有共享节点的路口。内置样板的通道间距需足够，不用一个通用自动修图系统解决输入错误。程序负责从样板生成几何，本批不增加随机路网生成器。

### 分岔流量

沿用圆管等效阻力 `R_e = 8 μ L_e / (π r_e⁴)`。每条边统一规定正方向，流量为 `Q_e = (p_from - p_to + h_e) / R_e`；普通边 `h_e = 0`，心脏泵段给出沿边正方向的压升。泵段仍有普通管道的正阻力和可通行几何。所有节点满足有向流量收支为零，固定一个参考节点压力消除整体压力平移自由度。

推荐对小图的节点压力方程使用 `f64` 稠密 Cholesky，手写小型求解实现，不引入线性代数依赖。正阻力、连通图和固定参考压力使约化系统对称正定。首版面向几十个节点的小图，实际样板保持在 16 个以内。

本批几何、黏度与阻力固定，只有单个泵压随时间变化：初始化求一次单位压升下的压力与流量，运行时乘当前脉动压差。压力滑块仍能即时调节；无需每个物理步重新分解矩阵。以后增加动态阻力或多个独立泵时再调整更新方式。

其他选择包括沿用针对某个固定分岔的解析公式，或现在接入稀疏迭代求解。前者限制拓扑，后者在当前规模下增加求解与依赖选择工作；稠密方法只承担小地图，扩到大图时依据规模测量另作决策。

该方案是针对本项目纯阻力网络的推导。[SimVascular 血管元件](https://simvascular.github.io/svZeroDSolver/class_blood_vessel.html) 提供压力、流量与阻力模型参考；本批不采用其完整 RCL、狭窄或生理参数模型。

### 局部速度与分岔过渡

普通管段继续采用圆管中心截面的抛物线速度，按所属边的 `Q_e`、半宽和路径切向计算。位置查询支持线段投影，返回边 ID、路径位置、横向距离与切向。

路口附近混合相邻边的速度，权重随到路径的距离平滑变化，并限制在相邻连通边的通道范围内。权重按物理路径长度定义，不能因一条边被细分为更多折线段而偏向该边。远离路口恢复单管段结果；管道外不提供血流，临近外墙的采样应衰减，避免持续将细胞推向墙外。准确权重函数、过渡距离和展示箭头间隔属于实现调参，但不能换成另一套流体算法。

这是分岔处的游戏速度近似：0D 网络守恒不表示局部二维场严格无散度，也不保证细胞按精确流量比例进入各支路。需要通过真实细胞穿过分流和汇流处检查是否发生持续停滞；如必须更换算法才能达到本批通行目标，应报告问题后再决定。

局部网格压力投影可作为后续绕流研究方向，它需要二维边界、压力求解与物体耦合。[Bridson 课程](https://www.cs.ubc.ca/~rbridson/fluidsimulation/fluids_notes.pdf) 与 [Batty 等的固液耦合研究](https://www.cs.ubc.ca/labs/imager/tr/2007/Batty_VariationalFluids/) 提供方法依据；本批不加入这个求解器。

## 模块与接口方案

继续使用现有两个 crate，职责按既定世界架构落地，避免为后续系统建立空框架。

| 所属模块 | 拥有的内容 | 提供给下一层 |
| --- | --- | --- |
| `simulation` 的地图模块 | `MapDefinition`、节点与边、出生点、区域地标、内置样板、派生静态几何 | 只读地图、位置投影、墙与地面几何 |
| `circulation` | 阻力、单位压升解、实时各段流量与局部采样 | 按位置采样速度、流量摘要与箭头输入 |
| `runtime` | 当前场景、唯一 Rapier 世界、固定步时间、机器人与细胞 | 保留 tick/pause/single_step/reset；增加明确场景选择 |
| `view` | 静态地图显示数据、动态对象和调试数据 | Godot 无关的数据结构 |
| `godot_bridge` | 场景选择、移动与调参转换、几何和快照转换 | Godot 字典与数组；不持有第二份权威地图 |
| Godot 世界场景 | 世界绘制与地标、Camera2D、CanvasLayer HUD | 输入意图与可读反馈 |

建议保留默认 `Simulation::new(Config)` 和 `BloodLab` 的原实验场行为，为世界样板增加显式构造或选择入口。`reset` 重新创建当前所选样板，并保留现有暂停和调参语义。两个场景复用同一运行协调与细胞逻辑；允许原跑道专有几何暂留用于实验对照，不复制一套物理推进器。

静态输出扩展为权威墙边界、地面填充几何、地图范围、地标；动态输出保留机器人、细胞与统计，增加适用于多段网络的箭头和流量摘要。原实验入口所需字段继续可用。具体函数命名和桥接字段在实现计划中固定后交给各 worker，变更必须由主 agent 统一协调。

Godot 新增世界场景作为默认启动入口，保留 `lab.tscn` 可单独打开。世界 Node2D 以统一的 24 px/单位绘制，Camera2D 跟随机器人，HUD 放在 CanvasLayer。每个活动场景仅有一个 `_physics_process` 推进模拟，两场景不同时运行。WASD、方向键、暂停、单步、重置与流向/碰撞显示沿用原操作。

先以 72 个红细胞为默认起点，按各支路长度分布并为机器人出生留空间。密度、图的具体尺寸、镜头跟随参数及泵压可按通行体验调整；保持现有自主运动方式和软体参数为基线。暂不承诺目标设备帧率或更高细胞数量。

## 开发顺序与子 agent 分工

算法和接口方案经用户确认后，主 agent 写出精确文件与类型约定，再派 sol medium 实施。

1. 地图与静态几何：一个 worker 负责地图类型、内置分岔样板和共享边界；交付可直接被循环和物理消费的定义。
2. 循环网络：接口固定后由另一 worker 负责节点求解与局部速度采样；可以与地图细节实现并行。
3. 接入与画面：在静态/动态输出契约确定后，由第三个 worker 负责 bridge、世界场景、镜头与 HUD。
4. 主 agent 负责 runtime 集成、细胞驱动接线、已有实验入口兼容、文档与集中验证；任何新增算法或重要边界决策返回用户确认。

每个 worker 有独立文件责任，修改共享类型必须先协调；禁止覆盖用户和其他 agent 的修改。后续战斗、区域调度与大地图规模验证仍按世界架构的依赖顺序推进，本轮不提前创建它们的实现。

## 完成依据

- 共享几何产生无内部隔墙的分岔和汇流通路；显示的血管与实际碰撞相符。
- 纯阻力网络通过一个独立手算的串并联回路案例，检查流量比例、节点收支与泵压缩放。
- 真实软体在小地图上推进，能通过分流与汇流位置；记录面积、越壁、各支路经过情况及实际求解耗时。使用已有模拟入口扩充适当探针，不另建性能框架。
- 暂停、单步、重置、机器人操控与原软体检查继续适用；新增永久测试只覆盖新图求解和分岔通行的关键缺口，不在多层重复验证相同规则。
- 集中执行 `bash scripts/check.sh`；若新默认场景替换原加载入口，应覆盖原实验场和新场景的必要加载检查。
- 图形验证只自然运行后截图查看，不自动发送移动输入、点击控件或跑交互流程。跟随镜头的操控体验与路线选择由用户人工验收。

本方案已获批准。扩展空间通过地图定义、网络流量、局部速度采样、物理驱动及显示数据的明确接口保留；后续更换流体算法时另行确认，不预先建立通用插件框架。
