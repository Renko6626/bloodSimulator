# 细胞近场软体与远场数量模型方案

2026-10-29。用户已选择“远场数量/密度，近场构造软体”。用户随后以“ok 开干。”确认下列具体范围、输运模型、数量归属与接口，生产实现与本地验证完成，硬件及联合长测尚未验收。已授权的Godot视野剔除已完成，见[记录](../../research/2026-10-29-static-background/README.md#后续已授权细胞视野剔除)。

## 为什么需要单独做

当前72个十二节点红细胞全部存在于同一个Rapier世界，`cell.rs`显式can_sleep(false)。LBM窗口只限制局部流体精算/marker交换，窗外细胞仍做背景拖曳、约束与碰撞。现有纯Rust延长诊断约9.62ms，其中Rapier约3.70ms；窗口化可能减少其中一部分，不能假定全部消除，更不能解释或解决所有Godot整帧开销。

原[世界架构](2026-10-21-world-architecture-design.md)已将普通远场群体定义为抽象指标，不要求重建每个普通红细胞身份。这次把该方向落到细胞交通，不扩展感染/战斗/任务或全图化学场。

## 已选路线与代价

- 近场：真实十二节点软体，原材料、Rapier子步、接触、LBM有限阻力耦合保持。
- 远场：维护非负数量与由数量/容量计算的密度，按血管图输运，不保存普通红细胞身份、粒子坐标或变形。
- 出入详细范围只在视野外发生。物体退休后其数量归还远场；进入时从远场扣除实际构造数量，不凭空刷新补满。
- 窗口化改变了物理近似；不能再以与全量模拟逐帧f32相同作为验收条件。

备选为保留每个远场细胞中心/位置，或直接冻结窗外软体。前者继续保留全局个体状态，后者会停住远场循环；用户已经选择群体表示，因此不实施这两条路线。

## 第一版详细范围建议

建议以机器人位置为中心：

- 新激活范围72×72世界单位（半边长36）。
- 已存在软体保留到其完整AABB离开80×80范围（半边长40）再退休，避免在同一条边界反复生成/回收。
- 不是照相机边缘切换。当前视野约53.3×33.3；LBM48×48按16单位块迁移，边界最远可能距机器人32，因此激活框覆盖这两者并有余量。
- Rust不读取Godot相机对象。此初版覆盖当前固定缩放/视口；变焦、超宽视口或更大流体窗口需重新确定尺寸契约。
- 窗口内局部软体数量由交通密度决定，不强制永远72个，不通过删除/重生维持恒定压力。第一版单局总量仍沿用Config.cell_count作明确数量预算，默认72；后续提高密度另测规模。

72/80是已确认的首版配置，不是最佳尺寸或性能保证。验证场原本已把72细胞集中在玩家附近，初期可能全部仍活跃，不能期待仅靠改窗口就显著加速此工况。

## 远场输运建议与明确近似

建议首版使用血管段级均匀混合数量模型，每0.2模拟秒更新一次。每个血管区间的抽象库存为f64非负数量，普通群体允许分数；近场软体按整数计数。其余时刻不推进远场粒子/碰撞。

- 有向输运跟随当前GraphFlow的符号和分叉流量比例；零流量时不输运。
- 固定使用当前解析背景平均速度 `u_e=Q_e/(πR_e²)`；长度L、数量N的远场区间在Δt内向下游输出 `ΔN=N×min(1,|u_e|Δt/L)`。先用纯CPU独立算例验证。现有graph背景速度使用Q/(πR²)，LBM开口是二维通量；本次不改已有流体公式，也不把两者误当同一种数量通量。首版群体是游戏交通近似，不承诺近远交界的生理通量精度。
- 数量模型以72×72激活框切分中心线弧长区间。窗口外区间按上述公式输运，窗口内区间允许暂存未实体化数量，仅供构造、不继续抽象输运。分叉在原图节点交换数量；同一血管边两端不连通的远场区间不瞬间混合。窗口移动后按弧长重叠比例把旧均匀库存分配到新分区；完全进入近场的份额仍在对应edge/弧长区间中，未生成前不会被丢弃。
- 每段库存均匀混合。一次显式更新从旧库存同时计算流入/流出，不让新到达数量在同次更新连续跨多段。原图节点汇总上游输出后按下游|Q|归一分配；进入近场的份额存入相应窗口内区间。每个区间只有一个有向下游端，单次输出不超过库存；零长度切点不创建库存单元。因此数值非负与数量收支可以直接核对，无需追踪每个细胞旅行时间。
- 这仍有混合/数值扩散，不保留远场密度团的精确到达时间。若玩法以后要求细胞团沿途传播，应另选一维输运模型；当前不增加这一套算法。

每个远场连续区间只保存数量与所属边/弧长端点；密度由数量/有效长度与管宽计算，不冗余存两份权威值。密度仅为按有效管宽/长度计算的显示/构造量，不混入LBM密度rho；本方案的数量通过率已经固定，实施时先验证公式再接物理。

## 交接规则与数量归属

- 总量账：`活跃软体数 + 所有区间的抽象库存 = 初始单局总量`。窗口内未构造的份数也属于同一份区间库存，按其edge/弧长绑定，不再另设一份重复计数的边界余额、请求队列或恢复记录。72～80保留带允许真实软体与其他抽象份数共处，但每一个数量只能属于其中一种表示。
- 近场构造只消耗窗口内区间已有的整数份额；运行期位置限制在半边长32～36的外缘带（64×64内部作为当前视野的保护范围），避开机器人、墙与现有细胞。分数不足1或没有合法位置时，数量原样留在该区间；移窗时与其他库存一样按弧长重映射，禁止补填到可见内部，也不累计待补发请求。
- 退休按完整软体AABB离开保留框判断，通过现有PhysicsWorld.remove_soft_body移除；只加回一个群体单位，不同时保留该个体副本。
- 初始分布直接复用现有world_cell_centers或validation的局部seed列表。激活范围内的初始中心原位构造软体，范围外每个中心向对应edge/弧长区间贡献1，再丢弃该普通个体位置；因此world的全图分布与validation的局部分布不会被改成同一均匀密度。初始构造在显示前完成，可见内部只在这次构造；之后遵守外缘规则。
- 近场中细胞自行穿过分叉，由真实碰撞和流体推进；远场分叉才使用图流量比例。两种方式不会同时更新同一数量。
- 暂停停止远场时钟；单步使用同一模拟时间；reset重置同一模式和初始总量，保留现有用户参数语义。

## 模块与接口建议

| 所属 | 内容 |
| --- | --- |
| 新 `simulation/cell_population.rs` | 范围配置、远场区间库存、输运与激活/退休决策；不持有Godot对象，不推进第二个Rapier世界 |
| `runtime.rs` | 唯一Rapier世界与活跃handle列表；帧边界执行已决定的移入/移出，再走原机械子步/LBM |
| `cell.rs` | 原软体构造/材料；增加必要的合法放置与初速度设置复用，不复制软体模型 |
| `view.rs`/bridge/HUD | cells轮廓仅含活跃软体；另外明确显示全局总量、详细数量和未实体化数量（包含远场与近场待构造份数），不把本地cells.size误标成全局总数 |

建议新增显式 `--local-cells` 验证入口，默认关闭，保留原全量模式和旧实测作为对照。初轮先支持内置world/验证场，原loop lab不接群体模式。上述模块与snapshot字段是本方案已确认的新边界，不从本次绘制优化中顺带引入。

## 验收与范围

1. 纯CPU数量测试：停流不迁移、两段串联收支、分叉比例、窗口移动的库存拆分/合并不增减总量。
2. 激活/退休不重复计数；无法生成时库存不丢、也不生成重叠软体；暂停/单步/reset一致。
3. 真正近场接触、机器人推挤与LBM仍正常；连续进入/离开范围不在可见区域突然生成/消失。
4. 同输入对照记录活跃软体数、远场库存、软体创建/移除成本、Rapier/LBM/整步与完整渲染帧；分别看稀疏和本来就密集的窗口。
5. 首版不保证严格封堵、全局反压或精确远场到达时间。不扩到白细胞/敌人/重要对象，不引入新依赖、调度线程池、恢复队列或数据库。
6. 细胞模式改变后旧validation初始细胞身份/位移指标不能原样套用，旧全量模式原证据保留，新增群体模式按数量与近场行为验收。
