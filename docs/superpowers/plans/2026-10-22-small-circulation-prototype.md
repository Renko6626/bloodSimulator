# 小型体循环原型实施计划

> 执行方式：本会话直接实施，遵守用户提供的 AGENTS.md。用户已确认整体架构并要求继续开发，本轮按下述收敛范围推进。

**目标：** 一条连续封闭的极简体循环血管，软体红细胞随流绕行，灰色圆形机器人以 WASD 自由移动并受到轻微顺流漂移。

**架构：** 沿用 Rust 唯一模拟状态、Godot 输入与表现、GDExtension 接入。闭合血管几何独立于固定步协调器，碰撞、流速采样与绘制共用定义；显示数据分为稳定几何与动态快照。

**技术栈：** 保持 Rapier 0.36.1、godot-rust 0.5.5 和现有 Godot 4.7 接口，不引入重要依赖。

**设计依据：** [世界架构](../specs/2026-10-21-world-architecture-design.md) 与 2026-10-22 用户本轮要求。

## 约束与取舍

- 本轮只做一圈体循环；器官景点、战斗、区域装卸和远处指标暂留后续阶段。
- 采用跑道形封闭血管，只有一个总流量。等效圆管阻力 `R = 8 μ L / (π r⁴)`，`Q = ΔP / R`；二维显示采样圆管中心截面的抛物线 `u = 2 Q / (π r²) × (1 - d²/r²)`。
- 弯道按中心线切向延拓速度分布，是游戏近似；不是求解弯管流体。红细胞不反馈流场或全局阻力。
- 机器人每个物理子步采用移动意图加小比例流速作为目标速度，移除操作惯性；Rapier 仍处理实际接触。
- 默认尝试 72 个、每个 20 粒子的现有闭合软体。数量与拖曳参数以真实循环实验调整，不凭文档承诺密集接触能力。
- 小图先用全景俯视，便于观察整圈交通，保留暂停、单步、重置和必要调参。
- 当前分支已有完整未提交原型，原地续作，保留用户已有变更；不创建缺失这些原型文件的新工作树，不顺带提交全部工作区。
- 验证采用相关已有检查、少量关键生产行为测试、一个真实软体循环探针和最多截图查看；不自动发送玩家输入或操作控件。

## 审阅重点

- 速度采样在直道与弯道衔接处方向连续，关闭压力后不凭空存在驱动。
- 内墙必须是有孔回路的一部分，绘制和真实碰撞保持一致。
- 红细胞不靠传送或删除重生完成循环，保留真实软体接触。
- 操控测试只覆盖生产模拟；操作手感与密集交通趣味性保留人工验收。
- 完成后进行一次整体只读代码审阅；只修复与本轮核心功能有关的实际问题。

## 实施记录

### 实际实现

- `vessel.rs`、`runtime.rs`、`view.rs` 已按职责拆分；原 `world.rs` 已移除。仍保留两个原有 crate，无新增依赖。
- 稳定墙体单独传入 Godot，动态快照包含软体轮廓、机器人、流向与统计。
- 初始红细胞分三列错开布置，为机器人留出空间；循环过程中没有传送、回收或重新生成。
- 机器人速度每个子步直接取 WASD 意图与 8% 局部流速之和，取消原 `robot_response` 操控平滑。
- 图形画面已截图查看，未自动输入移动指令或操作面板；截图见 `docs/images/circulation-prototype.png`。

### 软体研究结果

研究参考为 [Rapier 0.36 软体文档](https://rapier.rs/docs/user_guides/rust/soft_bodies/) 及本机锁定版本源码。原生 `disk` 使用闭合表面与面积保持，表面参与细胞间及刚体接触。本轮只使用现有约束求解器。

第一轮沿用统一 12 Hz 软度时，72 个细胞在 60 秒内全部完成绕行，但最大面积偏差达 50.04%。新增真实密集交通回归在 5.15 秒捕获了面积比降至 0.7493 的问题。定位发现 `.softness(...)` 同时覆盖膜边、弯曲与全局面积约束，原参数使拥挤下的面积约束偏软。

修正为膜边 12 Hz、面积约束 30 Hz 后，再运行：

```bash
cargo run --locked -p simulation --example circulation_probe -- 72 60
```

| 测量 | 结果 |
| --- | --- |
| 模拟时长 | 60.0 秒，3600 固定步 |
| 完成至少一圈 | 72 / 72 |
| 圈数最小 / 中位 / 最大 | 1.200 / 1.882 / 2.486 |
| 有软体接触的步数 | 3600 / 3600；计数为接触见证，不是独立碰撞对数量 |
| 最大面积偏差 | 14.00%，相对各细胞初始轮廓面积 |
| 最大包围框长宽比 | 3.201，可见明显变形 |
| 最大粒子越壁距离 | 0.0000；按每个固定步采样，与理想几何边界比较 |
| 求解平均 / p95 / 最大耗时 | 8.332 / 12.337 / 26.431 ms |
| 探针总墙钟时间 | 31.68 秒，含快照和统计 |

测量环境为 Linux x86_64、Intel Xeon Gold 6330 @ 2.00 GHz，Cargo dev 构建，依赖沿用项目的 opt-level 2 设置。求解耗时包含细胞驱动和 Rapier，不含 Godot 绘制；该结果不能当作目标玩家设备帧率。

结论：现有软体能支持本轮默认数量下的挤压与连续循环，无需替换求解器。尚未验证更高密度、长时间堵塞、复杂分岔或完整大地图负载。
