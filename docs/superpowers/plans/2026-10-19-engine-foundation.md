# 引擎与基础设施实施计划草案

> 后续实施者应读取设计草案，并使用 superpowers:executing-plans 按任务推进。本文是后续工程计划，本次仅编写文档与建立公开仓库。

**目标：** 建立能运行、观察和调参的血管物理实验工程。

**架构：** simulation 独立保存和推进物理状态，godot_bridge 转换输入与显示数据，Godot 负责输入和表现。全局 0D 网络单向驱动局部简化流场，局部流场驱动物体。

**技术栈：** Rust、Rapier 2D、godot-rust GDExtension、Godot 4；具体兼容版本在实施时核对并锁定。

**设计依据：** [设计草案](../specs/2026-10-19-blood-simulator-design.md)。状态：待进入工程实施，本文件不表示以下任务已完成。

## 全局约束

- 三周、单人、桌面、2D。先在本机 Linux 验证，不提前承诺跨平台打包。
- 唯一 Rust 模拟状态，simulation 不依赖 Godot，不重复推进物理。
- 优先验证 Rapier 原生二维软体；不默认新增自研软体或流体依赖。
- 固定小场景，不实现关卡、敌人、武器、世界流式加载或双向流体反馈。
- 新的重要依赖、模块边界或替代方案须先确认；版本不兼容时报告具体决策点。
- 不自动跑交互流程。构建和必要加载检查之外，以截图与人工体验验证画面和操作。
- 新增永久测试仅覆盖关键行为或具体不变量，避免复制算法和构造庞大验证框架。

## 任务 1：工程接通

**文件责任：** 根目录 Cargo.toml、Cargo.lock；crates/simulation/Cargo.toml 与 src/lib.rs；crates/godot_bridge/Cargo.toml 与 src/lib.rs；godot/project.godot、扩展描述与启动场景；scripts/ 下必要入口；README.md。

**接口：** simulation 暴露明确的步进入口与只读显示数据；bridge 接收输入、调用步进并返回结果。具体 Rust 类型在实施本任务时确定并记录，不建立通用事件框架。

- [ ] 核对 godot-rust、Rapier 发布版本和本机 Godot 的兼容性，锁定版本并保留 Cargo.lock。
- [ ] 建立 workspace；bridge 为 cdylib 并依赖 simulation，simulation 不引入 Godot 类型。
- [ ] 用最小显示对象接通扩展，确认 Godot 能加载并获得 Rust 输出。
- [ ] 建立固定步进的唯一调用位置，集中说明时间单位与显示比例。
- [ ] 增加本机构建和启动入口，README 只记录实际运行成功的命令。
- [ ] 运行 cargo fmt --check、cargo check --workspace 和 Godot 无界面导入／短时加载检查，记录真实结果。

**完成证据：** workspace 编译成功；Godot 加载扩展无相关错误；文档中的构建和启动入口可用。此时不宣称软体或手感验证完成。

## 任务 2：软体实验场与调试能力

**文件责任：** simulation 中的 world、cell 与 robot 模块；bridge 显示数据转换；Godot 实验场绘制、输入、调试界面及集中参数。

**接口：** 输入为移动意图与调试控制；输出为机器人位姿、细胞轮廓和本步统计。渲染只消费数据，不修改 Rapier 状态。

- [ ] 用 Rapier 原生二维闭合软体创建红细胞近似，记录轮廓分辨率、面积约束与阻尼参数。
- [ ] 建立有分岔和收窄段的静态血管边界，加入可自由推进和制动的刚体机器人。
- [ ] 将细胞变形轮廓和机器人位姿绘制到 Godot，保持模拟坐标与像素转换一致。
- [ ] 加入暂停、单步、重置与参数入口；显示细胞数量、求解耗时和碰撞轮廓。
- [ ] 对暂停不推进、单步只推进一次和重置恢复初始场景进行简短行为检查，尽量复用同一入口。
- [ ] 用真实生产模拟执行一个简单软体压缩与释放检查，观察面积、恢复和数值有效性；不预设未经实验支持的严格误差阈值。
- [ ] 集中执行受影响的 Rust 检查、Godot 加载检查并截图；将人工操作体验保留为明确验收项。

**完成证据：** 编译及相关检查结果、实验场截图、实际采用的软体参数与已知限制。密集接触不满足需求时先报告，不自动开发替代求解器。

## 任务 3：0D 网络与单向速度场

**文件责任：** simulation 中的 circulation/network、circulation/field 模块及实验场配置；Godot 流向显示；README 使用说明。

**接口：** 网络输入为节点连接、血管阻力和压力边界，输出为节点压力与各段有向流量；局部场提供按模拟坐标采样速度的入口。物体推进读取局部速度，物体不回写网络或场。

- [ ] 实现小型连通阻力网络，以明确的压力边界驱动流量，内部节点满足流量守恒。
- [ ] 用一个解析可解的分岔网络验证流量分配与守恒；预期值来自独立手算，不复制求解过程。
- [ ] 加入周期性压力驱动；将网络流量通过明确的等效截面约定映射成局部简化速度场。
- [ ] 让红细胞接受流动驱动，机器人接受较弱扰动，相关系数集中可调。
- [ ] 加入流向显示，记录网络及局部场更新位置；不新增细胞移动边界或全局堵塞反馈。
- [ ] 集中运行相关检查与 Godot 加载检查、截图，并更新运行说明和未验证项。

**完成证据：** 网络关键检查通过，分岔交通可观察，README 可用于运行实验场；“逆行仍可控”和拥堵趣味性由人工体验评估。

## 审阅重点与暂缓项

审阅重点是唯一物理步进、暂停／单步、单位与流量映射、软体实际表现及依赖兼容性，不扩展成完整生理学验证。

性能测量先报告场景规模和实际耗时，硬件与细胞数量目标确定后再设预算。二维网格流体与 Salva 比较、局部双向耦合、全局堵塞反馈需要另写有界技术验证方案。
