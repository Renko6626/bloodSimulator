## 实施细节

- 锁定 Rapier 0.36.1（原生二维软体）、godot-rust 0.5.5（api-4-7）；本机 Godot 4.7.1、Rust 1.98.1。
- 模拟接口：Simulation::tick(MoveInput)、set_paused(bool)、single_step(MoveInput)、reset()、snapshot()。tick 只执行一个固定步；Godot _physics_process 是唯一实时调用位置。
- 显示接口只传快照；静态墙体和流向也由模拟层提供，避免绘制与碰撞几何分叉。
- 首轮阻力网络固定为一个入口、一个分岔节点、两个出口。节点压力用电导加权的边界压力直接求解，无通用矩阵库。
- 固定小场景，闭合出口用于观察积聚，需手动重置；不引入对象回收、生成队列或循环地图。
- 验证集中执行：Rust 格式、检查、关键行为测试；Godot 导入和短时加载；画面最多截图，不自动操作控件。

## 实际参数与验证

- 默认场景 17 个细胞；每个细胞为 20 粒子闭合轮廓，半径 0.7、总质量 1、约束频率 12 Hz、约束阻尼比 1、线性阻尼 0.5、粒子碰撞半径 0.07。Rapier disk 默认启用面积保持。
- 模拟 60 Hz，每步 2 个子步；机器人碰撞半径 0.85、质量 3、速度 4，流动扰动系数 0.12。显示 34 px / 单位。
- 网络阻力为入口 2、上支路 3、下支路 6，出口压力均为零；入口均压 12，脉动幅度 30%，频率 1.2 Hz。等效深度 1，截面面积=2×局部半宽；抛物线峰值速度=1.5×Q/面积。
- `bash scripts/check.sh`：最终完整执行通过，包含 `cargo fmt --all --check`、`cargo check --locked --workspace`、`cargo test --locked -p simulation`、`bash scripts/build.sh` 及下列 Godot 导入和运行检查。
- Rust 关键检查：暂停 / 单步 / 重置、解析分岔流量、真实软体压缩与释放。压缩测试使用生产细胞构造，在 Rapier 中由两块运动板挤压后放开；接受标准为可见压扁、面积误差小于 20%、释放后长宽误差各小于 20%，只是宽松的原型标准。
- 实测初始面积 1.5142、宽高 1.40 / 1.40；压缩后面积 1.4281、宽高 1.8674 / 0.8604；释放后面积 1.5117、宽高 1.2832 / 1.5020。测试经过 600 个 1/120 秒物理步。
- `godot --headless --path godot --editor --import --quit`：通过，扩展加载成功。
- `godot --headless --path godot --fixed-fps 60 --quit-after 180`：通过，无脚本或扩展错误。
- `DISPLAY=:2 bash scripts/run.sh --fixed-fps 60 --quit-after 2`：图形启动入口执行通过。图形场景自然运行约 8 秒后截图查看，已修正面板底部裁切和墙外流向箭头；未自动点击、填写或发送移动输入。图形环境为 Mesa llvmpipe，捕获时出现不支持调整 VSync 的驱动警告。
- 按 requesting-code-review 技能进行一次只读独立审阅，未发现核心问题；没有重复运行测试或扩大范围。

## 当前限制

- 封闭出口会积聚细胞，需手动重置；没有循环地图或重新生成系统。
- 压缩测试只证明一个简单接触案例，不能证明密集交通、通过窄口或战斗场景的整体稳定性。
- 单步求解耗时显示最近一个物理步，包含驱动和 Rapier 求解，不含 Godot 绘制与快照转换；本次不设性能验收预算。
- 调参只开放压力、机器人速度、细胞流动阻力；轮廓与软体参数在 Rust Config 中集中修改。
- 人工移动手感、逆行控制、拥堵趣味性及其他平台仍未验证。
