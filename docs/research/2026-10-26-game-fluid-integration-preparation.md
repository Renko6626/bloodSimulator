# 游戏流体接入准备

2026-10-26。用户接受当前约 6 ms 的研究基线，并要求准备接入游戏。本文记录代码核对、可选接入范围及需要确认的边界，不表示新增求解算法或模块接口已获批准。上一阶段的性能优化保持暂停。

## 已有基础

- 正式工程采用 Rust simulation、GDExtension bridge 与 Godot 展示；Rust 是唯一物理状态所有者，60 Hz、每帧两个机械子步。
- 正式世界使用血管阻力图与解析局部速度，72 个半径 0.7、质量 1、12 节点细胞；碰撞和绘制几何由同一地图生成。
- 研究候选为有限阻力 Stokes、ω=0.5、压力初值复用及内核优化，流体与 Rapier 各四线程。64²/64 细胞六秒整步均值 5.92–6.06 ms，已获用户阶段性接受。
- 当前模拟边界和待办见[状态文档](../STATUS.md)，测量口径见[流体优化报告](2026-10-26-stokes-kernels.md)。消费级目标设备尚未实测，接入不再以前期 5 ms 为先决条件。

## 接口核对

`crates/simulation/src/runtime.rs` 的 `Simulation::step` 是统一推进位置，目前按“更新网络 → 设置机器人速度 → 逐粒子解析流速驱动 → Rapier”执行。接入真正的流固反馈时，同一细胞不能再同时保留旧 `cell::advect` 和一套完整流体冲量驱动；需要明确何处由哪种规则驱动。

`robot.rs` 每子步设置移动目标速度，机器人尚未参加研究耦合实验。机器人目标速度、流体受力及 Rapier 推进的顺序需要在接入设计中固定，避免后写速度覆盖已经施加的反馈。

`map.rs` 与 `map/geometry.rs` 是真实管壁来源；局部流体不能另外维护一套与碰撞不同的弯管或路口定义。`circulation/graph.rs` 已输出节点压力及边流量，可以作为局部边界驱动的来源，但圆管网络与二维局部流场的换算需明确定义。

`godot_bridge` 继续转换输入与快照，Godot 继续绘制和采集输入，不重复推进流体或接触。现有暂停、单步和重置语义保留。研究程序一次性初始化 Rayon 全局池的做法不能直接放进每次游戏重置；池的创建与生命周期须按正式入口组织。

## 尺度与参数

保持时间单位为秒、质量单位不变时，按细胞直径换算的长度比例为 `1.4 / 0.09 ≈ 15.56`。这是可选标定起点，不是已批准的单位体系。

| 项目 | 研究值 | 按上述长度比例换算 |
| --- | ---: | ---: |
| 方域边长 | 1 | 15.56 游戏单位 |
| 64² 网格步长 | 1/64 | 约 0.243 游戏单位 |
| 细胞半径 | 0.045 | 0.7 游戏单位 |
| 表面粒子半径 | 0.0045 | 0.07 游戏单位 |
| 预测接触距离 | 0.002 | 约 0.0311 游戏单位 |

正式世界管宽约 6.2–7.0，原研究方域上下直壁的位置不能作为实际管壁。研究求解器的 x 周期、上下无滑移矩形通道也不能直接替代弯管、分流与汇流边界。全地图维持相同空间精度需要更多网格，不能把 6 ms 当作全图预算。

阻力还存在独立差异。研究中每个细胞四标记总 Γ=0.25、质量 1；忽略流体自身响应时，刚性平移近似的速度松弛时间约为 `m/Γ=4 s`。正式 `cell::advect` 的参数 20 是解析积分的速度松弛率，其时间尺度为 `1/20=0.05 s`。这两个值相差 80 倍，但作用点和流体反馈也不同，不能据此直接把 Γ 调到 20。接入需要带背景血流核对细胞跟流响应；原六秒主测为零背景流、两个细胞受短时外力，不足以确认当前游戏手感。

研究黏度归一为 1，正式网络等效圆管黏度为 0.05；二维局部流场与圆管网络不能仅通过复制数值完成标定。

## 接入范围选项

| 路线 | 首批交付 | 主要取舍 |
| --- | --- | --- |
| 现有世界中的固定局部窗口，建议优先选择 | 在一个选定位置使用 64² 局部流体，沿用整张世界地图；窗口外继续网络解析驱动 | 直接服务现有游戏，但须先确定并验证不规则管壁、开口边界、单位与驱动衔接；当前直管求解器需要扩展，性能重新测量 |
| 先接 Godot 直管场景 | 把已验证的流体与软体通过正式 Rust/Godot 通路展示，并接入机器人操控 | 更快观察局部手感，保留既有边界；仍不能代表现有分叉世界的正式流体替换 |

首批不引入移动窗口、LOD 或全局堵塞反馈，以减少同时需要确认的机制。若选择固定局部窗口，下一份设计须明确固壁和开口的离散方式及求解方法，不能把“增加几何遮罩”当成现有 FFT/Thomas 已支持任意血管的证明。新增算法与性能变化须明确展示。

建议延续 `Simulation` 统一调度，局部流体在 simulation 内部保持独立职责；不让正式代码依赖 `docs/research` 路径，不建立通用后端插件框架。具体文件边界与接口在路线确认后的设计中确定。

已核对运行协调、细胞驱动、机器人控制、地图、图流量、bridge 和研究候选入口；完成上表尺度计算。没有修改正式模拟、引入依赖或启动新性能实验。
