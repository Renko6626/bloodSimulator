# RTX3060端到端复测

2026-10-30，用户要求先提交推送实现，再做实卡测试。实现25e29e4已推送feat/godot-static-background；本轮不改产品代码。旧版为d0dfa07，新版包含细胞Mesh、LBM合批和HUD10Hz。

## 主测：往返对照有整帧收益

同一轮同一GPU，GL compatibility、1280×800、禁用vsync、显式移动回放、Local细胞、Fine/14格子步。依次运行旧版A→新版A→两个短控制→新版B→旧版B；每个主测120预热＋3600测量步，各3599个有效帧间隔，主测不截图、不加GPU查询、不固定GPU频率。

| 主测 | 均值 ms | p95 ms | p99 ms | 最大 ms |
|---|---:|---:|---:|---:|
| 旧版A | 14.421 | 17.740 | 20.115 | 29.717 |
| 新版A | 12.039 | 14.774 | 17.232 | 28.265 |
| 新版B | 11.907 | 14.545 | 15.209 | 26.121 |
| 旧版B | 14.736 | 18.261 | 20.255 | 30.749 |

合并两轮原始间隔，各7198个样本；分位数从合并样本重算，不平均p95：

| 合并指标 | 旧版 | 新版 |
|---|---:|---:|
| 整帧均值 ms | 14.578 | **11.973** |
| 整帧p95 ms | 18.092 | **14.684** |
| 整帧p99 ms | 20.212 | **15.676** |
| ≤16.667ms的间隔比例 | 68.17% | **99.31%** |
| Rust整步均值 ms | 8.695 | 7.864 |
| LBM均值 ms | 4.566 | 3.795 |
| LBM内读回等待均值 ms | 1.998 | 1.766 |
| snapshot/HUD刷新均值 ms | 0.799 | 0.738 |
| draw calls均值 | 239.423 | 199.739 |

本轮整帧均值下降17.9%，p95下降18.8%，两个方向都观察到新版更快。LBM、等待和Rust是包含关系，不可叠加节省量。总收益大部分落在Rust之外的表现/引擎路径，但没有直接逐段测World脚本与原生引擎CPU，不能把约2.6ms全归给Mesh。仍有约28ms尾帧；结果覆盖此验证场，不能称所有负载、开启vsync或实际桌面帧节奏稳定60FPS。

## 分项短测：归因有限

各120预热＋1200测量步，以下仅与主测的相同1200步前缀比较，不能直接与整段3600步均值比较。render-only指新Mesh＋10Hz HUD、旧LBM；其余单因素使用旧版其他部分，库和脚本哈希均已核对。

| 同一1200步前缀 | 帧间隔均值 ms |
|---|---:|
| 旧版A / B | 16.906 / 17.359 |
| 新版A / B | 14.130 / 13.778 |
| Mesh＋HUD，旧LBM | 14.168 |
| 仅LBM合批 | 17.240 |
| 后补仅HUD10Hz | 20.101 |
| 后补仅Mesh | 20.577 |

前两项短控制支持表现路径很重要，但单独LBM合批没有建立整帧收益。后补HUD/Mesh时环境明显变慢：GPU图形频率中位数（整例含启动/预热采样）降到427/435MHz，连未改动的Rapier也从主测前缀约2.84–2.95ms升至3.89/4.65ms。它们不能用于精确分摊Mesh和HUD，也不能仅凭20ms判定单项修改导致退化。新版主测图形频率中位数约660MHz，旧版约525/532MHz；功耗/频率响应与工作形态相关，尚未唯一归因。本轮保留全部结果，不继续扩大控制矩阵或自动调硬件时钟。

可确定的工作量变化是普通帧submit20→8、draw calls239→200；不能把这些降幅直接换算为各组件的独立毫秒收益。
