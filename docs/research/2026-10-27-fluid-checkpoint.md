## 当前判断

当前 GPU Stokes 候选已能收敛，但仍不适合实时游戏。最近一次资源复用后的 RTX 3060 回放，单次求解均值仍约 46–184 ms；60 FPS 的整帧预算只有 16.67 ms，而当前模拟通常每帧需要两次局部求解，还要运行 Rapier 和渲染。

保留已经验证的代码和数据，暂停继续追逐单个 API 的开销。现有证据尚未证明：把当前离散和迭代流程进一步搬到另一种 GPU API，就能达到游戏目标。

当前可用路径：

- 默认 Godot 世界：血管阻力图和解析流速驱动。
- 显式 `--local-stokes`：固定双区域二维 Stokes，默认 CPU f64 稀疏 LU。
- GPU：独立实验后端，保留 FGMRES／MG、profiling 和回读缓冲复用；没有设为游戏默认。
- 云实例 `57949215` 已停止，实际状态 `exited`、目标／当前状态 `stopped`；磁盘数据保留。[最后一次停机回执](experiments/2026-10-27-modular-mg/validation/wgpu-readback-reuse/stop-receipt.json)

## 物理模型与近似

一句话描述：**血管阻力图提供背景驱动，固定局部 MAC 网格求二维准静态不可压 Stokes，细胞和机器人通过少量有限阻力标记与 Rapier 弱耦合。**

| 部分 | 当前实际做法 | 适用限制 |
| --- | --- | --- |
| 全局背景血流 | 固定血管图的阻力、泵压和节点流量守恒；管段内使用抛物线速度，路口混合 | 解析局部速度不严格无散度；局部细胞拥堵未反向改写全图阻力／流量 |
| 局部流体 | 二维、恒定黏度、准静态 Stokes：`-μΔu + ∇p = f`，`∇·u = 0` | 没有流体惯性或对流项；参数是游戏近似，未作真实血液流变标定 |
| 边界 | 固定血管几何的阶梯网格，固壁无滑移；窗口开口采用压力牵引 | 壁面精度受网格影响；开口压力来自图流校准，局部黏度归一化为 1 |
| 细胞与机器人反馈 | 每个物体 4 个内部阻力标记，按物体／流体相对速度施力，`ω=0.5` 与上一子步力混合，再求反馈场并回传反冲量 | 允许透流，没有严格不可渗透膜、排液或水动力封堵；一次弱耦合更新不等同于流固联合隐式解 |
| 细胞机械 | Rapier 二维软体，默认 72 个细胞、每个 12 个物理节点，膜边和面积保持 | 机械碰撞与流体排斥是不同机制，不能由“没有穿墙”推断流体模型正确 |
| 解析拖曳采样 | 12 个节点中查询 6 点，其余节点插值；局部权重增加时解析拖曳减弱 | 6 次解析采样、4 个流体标记和 12 个机械节点是三种不同数量 |

耦合时将标记力分配到网格 RHS；矩阵和流体掩码不会随细胞变形改变。这是目前能够复用固定分解／层次的基础，也意味着细胞没有作为移动固壁进入离散方程。

已做过的独立 CPU 容差长测支持某些背景血流近似保持宏观稳定，但个体轨迹会分岔。它不能证明本轮 GPU 候选长期可用或玩家无感。[既有精度／长时研究](2026-10-26-stokes-sparse.md)

## 离散与核心算法

局部离散使用 MAC 交错网格：速度在面上，压力在流体格中心。原始线性系统为：

```text
[ A  -Bᵀ ] [u] = [f + 开口牵引]
[-B   0  ] [p]   [      0     ]
```

A 是黏性速度块，B 来自相同面通量的散度。求解器中亦以 `C=-B` 写为 `[A,Cᵀ;C,0]`。压力块保持为零，没有用新压力罚项改变方程。

**CPU LU：** faer 0.24.4、f64，一次符号／数值稀疏 LU，固定区域内反复回代。没有显式构造整个逆矩阵。背景解预先计算并按泵压缩放，细胞只改变反馈 RHS。默认 `dt=1/60`、两个机械子步，通常每帧两次反馈求解；区域交接还会有准备开销。

早期 CPU 的热点是压力 Schur 迭代反复调用速度逆。联合 LU 利用固定 K，消除了每次求解的这一层 Krylov 循环。当前 GPU 方案仍需执行多轮 FGMRES／MG，因此 CPU 与 GPU 的比较包含算法工作量和精度差异，不能解释为同一计算单纯更换硬件。

**GPU 候选：** wgpu 27／WGSL、f32，先作 `K'=DKD` 缩放，再使用右预条件 FGMRES。保存预条件后的 Z，并用 Z 更新解；restart=32、最多 200 次迭代、rtol=1e-4。当前每个 RHS 从零初值求解。

- 分块预条件：负压力 Schur 块使用质量阵型近似，校正速度 RHS 后用 MG 近似解速度块。
- 速度 MG：受几何和连通性约束的聚合、平滑延拓、Galerkin 粗化；u／v 分量分开，避免直接合并不连通的近邻分支。
- 每层 3 次前／后 Jacobi 平滑，粗层不超过 64 阶并在准备阶段构建小逆；层次在 CPU 构建，算子上传后驻留 GPU。
- 默认每次预条件 2 个残差校正 V-cycle；也测过 1 次。减少循环可能增加迭代和解差，不能只看步数。
- 大向量、正交化、Givens 和小系统回代留在设备上，每 8 次外层迭代读状态；每个 dispatch 目前单独一个 compute pass。
- 状态／最终解回读缓冲现已在准备阶段创建并复用；拷贝与计算仍分别编码、提交。

回放验收将解还原到原变量，在原始 f64 K 上核对全系统相对残差、相对动量 RMS、连续性 RMS 均不超过 1e-4，并检查有限值。速度相对 LU 的 L2 差和压力最大绝对差另报。线性残差通过只验证代数方程，没有验证模型、离散精度、耦合或玩法。

## 范围与默认参数

| 项目 | small64 | wide96 | wide192 |
| --- | ---: | ---: | ---: |
| 矩形范围，游戏单位 | 16×16 | 48×48 | 48×48 |
| 网格 | 64² | 96² | 192² |
| 格距 h | 0.25 | 0.5 | 0.25 |
| 两个区域的有效未知量 | 7,400／5,689 | 8,191／7,309 | 33,192／29,565 |

有效未知量由血管掩码决定，不等于整个矩形格子数。wide96 同时改变覆盖范围和格距，不能只按 96／64 比例解释耗时。

实际局部默认仍为 small64，两区域中心约 `[-14,0]`、`[-10,-8]`。加载时分别准备，激活区域按玩家离边界的距离与 1 单位滞回切换，交接复用标记力历史和同一个 Rapier 世界。域边缘权重过渡到解析血流；未实现全图区域调度或双场连续融合。

n／h／两个原点可通过 `LocalFluidOptions` 在构建时配置，不代表已实现游戏内热调整。默认细胞直径 1.4、机器人直径 1.7；先前讨论的玩家直径 2.0、约 38×24 的镜头覆盖是候选，未变成正式参数。

## 关键实验结论

| 已做的工作 | 得到的结论 |
| --- | --- |
| CPU 速度块稀疏化、faer、压力预条件小试 | 有收益有限或变慢的配置；不能据此概括所有 CFD 求解方法。后续采用完整 K 的联合 LU |
| CPU 联合 LU 接入双固定区域 | 小范围局部路径可运行，固定分解复用有效；初始化、内存和交接另有代价 |
| 48×48／192² 完整模拟对照 | 开发机两轮模拟整步均值约 17.69／18.01 ms，尚不含渲染，已超过 60 FPS 帧预算；保留了已知驱动错误 |
| 旧 GPU GMRES32，仅对角块缩放 | GTX 1050 Ti 的 48 次真实求解均在 400 次后失败；不是可用的速度基线 |
| 新 GPU FGMRES／MG | GTX 1050 Ti、RTX 3060 均在已测样本上收敛，但单次求解仍为几十至数百 ms |
| profiling 与回读缓冲复用 | 找到主机命令组织、资源生命周期和设备 MG 的成本；复用净改善约 8%–22%，仍未接近实时目标 |

最新 RTX 3060 资源复用轮的正常求解均值如下。每格为双区域、四 RHS、两轮共 16 条记录；此表只比较 GPU 方案的同机前后版本：

| 网格／V-cycle | 复用前 ms | 复用后 ms |
| --- | ---: | ---: |
| 64²／1 | 56.12 | 45.80 |
| 64²／2 | 81.82 | 70.98 |
| 96²／1 | 98.54 | 76.97 |
| 96²／2 | 131.39 | 115.06 |
| 192²／1 | 118.49 | 106.11 |
| 192²／2 | 200.56 | 183.63 |

本轮 384 次回放全部通过，192 对前后版本的数值诊断和 dispatch／提交／回读计数一致。部分原创建阶段的等待移到了 map／poll，不能把原 create_buffer 计时全算成节省。

更早的同设备云端 CPU LU 回放均值约 0.77／0.60／3.85 ms／次，属于不同测量轮次，仅说明量级，不应据上述两张不同来源的表计算精确加速倍数。CPU LU 回放也不等于完整游戏帧耗时。

## 当前困难和未确定事项

1. **大窗口的驱动模型存在已知错误。** 窗口包含泵血管后，当前仅开口压力驱动缺少域内泵压升，出现反向流。提高分辨率或把 K 解得更准都不会补上缺失的驱动。
2. **所需游戏物理还未定清。** 少量有限阻力标记允许透流；真实封堵、局部拥堵的反馈强度、全图血流重分配分别需要什么精度，尚无产品验收标准。
3. **固定矩阵是重要前提。** 更换为移动不可渗透细胞边界后，现有矩阵／分解复用优势和 benchmark 适用范围需要重新评价。
4. **当前 GPU 执行粒度不合适。** 首轮 host profiling 中编码占约 45%–59%，细分约 95%–98% 集中在 encoder.finish；尚未区分内部 wgpu 与驱动成本。资源复用后编码仍大。
5. **设备侧也有显著工作量。** profiling 中 MG 平滑是最大 GPU pass 类别；约 23%–29% 的 dispatch 只有一个工作组。完整 Stokes SpMV 的约 0.1–0.5 ms 不能代表整个 MG／FGMRES 求解成本。
6. **同步和测量口径需要谨慎。** 计时可能改变等待位置，CPU／GPU 时间轴重叠；Vast CPU 非整机独占。Linux／Windows 矩阵及初始向量一致，后续动态向量的哈希并非全同，跨机比较不能当成严格控制输入的硬件加速比。
7. **动态范围与地图尚未完成。** 只有固定双区域，没有全镜头／全图覆盖验收；地图二次 Bézier 末项使用 `c*t`，与标准 `c*t²` 不同，仍待独立核对。

目前没有证据保证：继续降低局部 API 开销、迁移 CUDA、使用执行图或融合 kernel，就足以跨越当前性能差距。尚未实施 CUDA 后端、命令重放／融合、GPU LBM 或新模型。历史 LBM 属于不同物理与离散候选，不能直接作为同一个 Stokes 线性后端替换。

## 冻结与交接
