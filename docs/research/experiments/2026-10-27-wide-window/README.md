# 48×48／96² 大窗口实验

2026-10-27，用户批准试验。**扩大窗口没有出现计算量爆炸，但当前边界驱动在窗口包含泵血管后产生反向流，候选不能直接采用。** 已保留完整对照与诊断，正式源码、默认参数、依赖和 Godot 相机未改。

## 对照方法

从当前工作区冻结两个实验副本，均保留 faer 联合 LU、自然牵引开口、72 个十二节点细胞、六次解析采样、四个流体标记、两个机械子步及单一 Rapier 世界。两组均预计算两个窗口，中心保持 `[-14,0]`、`[-10,-8]`，沿既有真实 MoveInput 路线往返：

- 基线：每域 16×16，64²，格距 0.25；原点 `[-22,-8]`、`[-18,-16]`。
- 候选：每域 48×48，96²，格距 0.5；原点 `[-38,-24]`、`[-34,-32]`。

候选仅修改实验副本的 N、H 与两个原点；原 H 同时用于掩码、范围、点力密度和冲量积分，随之统一改变。标记阻力系数、松弛系数与物理半径保持。额外诊断接口只读，快照、CSV 和诊断都在 tick 计时之外。

固定 CPU 2–5、既有性能锁，release／offline／locked 构建，按基线→候选→候选→基线运行，每条 20 模拟秒／1,200 帧，共 4,800 帧。共享主机会有波动，不据此保证目标设备帧率。

## 性能与覆盖

| 指标 | 16×16／64² | 48×48／96² |
| --- | ---: | ---: |
| 两轮流体均值，ms／帧 | 2.784 / 2.957 | 2.607 / 2.919 |
| 两轮模拟整步均值，ms／帧 | 8.224 / 8.591 | 7.927 / 8.285 |
| 两轮整步 p95，ms／帧 | 10.580 / 10.717 | 10.622 / 10.961 |
| 整个模拟初始化，ms | 283.7 / 352.5 | 231.1 / 302.7 |
| 进程峰值 RSS，MiB | 37.35 / 37.38 | 33.51 / 34.03 |
| 两域速度＋压力未知量 | 7,400 / 5,689 | 8,191 / 7,309 |
| 每帧末活跃反馈细胞，均值／最大 | 4.65 / 11 | 27.79 / 38 |

计时接近，不能从短测认定有稳定加速；候选整步最大帧为 75.10 / 34.57 ms。矩阵仅给流体掩码内建未知量，因子填充也随几何变化，栅格面积不直接决定耗时或内存。RSS 包含整个进程及初始化临时量，不能作为精确因子载荷。

覆盖诊断采用**讨论中的** 1280×800、SCALE=24、zoom=1.4，即约 38.10×23.81 的视野；没有修改实际相机。候选轨迹中镜头内细胞中心全部处于完整反馈区，基线按细胞中心／帧累计的完整反馈比例约 32.37%。候选完整相机矩形位于域内的帧占 98.58%，起步阶段最差仍超出约 0.99 单位，不能宣称已经完成带缓冲的全镜头布局。当前 Godot 实际约 53.33×33.33 的视野仍宽于候选域。

上述性能和覆盖来自**流向有误**的候选轨迹。修正驱动后需要重新测量，不能将它们当成正确模型的最终表现。

## 发现：泵进入域内后缺少驱动

在任何机械步、细胞反馈发生前，共同完整反馈位置 `[-16,0]` 的初始水平速度：

| 静态配置 | 水平速度，世界单位／秒 |
| --- | ---: |
| 原范围 16×16／64²，h=0.25 | +2.5204 |
| 诊断对照 16×16／32²，h=0.5 | +2.4776 |
| 大范围 48×48／96²，h=0.5 | −5.1011 |

其他三个共同完整反馈采样点也发生反向。同配置两轮的保存细胞、流场及机器人坐标观测完全复现。

[网络驱动](../../../../crates/simulation/src/circulation/graph.rs)在 `pump_edge=11` 使用 `p_from - p_to + head`。单位工况下 `p_from≈−0.91393`、`p_to=0`、`head=1`，总驱动约 +0.08607，泵流量为正。泵段 17 个中心线点在原窗口内为 0 个，在首个大窗口内为全部 17 个。

[局部背景场](../../../../crates/simulation/src/fluid/mod.rs)只把网络压力投影到窗口开口，背景体力右端为零，没有在域内表达泵的额外压差。原小窗口位于泵下游，窗口边界压差可以驱动它；大窗口把泵包入域内后，该驱动缺失。线性系统仍可得到很小的残差，却在求解缺少泵驱动的问题。相同 h=0.5 的小范围静态对照保持正向，排除了“仅仅降低空间分辨率就导致反向”的解释。

本轮没有临时翻转速度、改压力符号或新增泵体力来掩盖问题。接入域内泵压差的具体方式涉及驱动模型，需先确认再实现。

## 数值与行为限制

两种副本各自通过原有 8 项单元、5 项集成检查；全部四条轨迹完成，均有六次交接，既有残差、冲量、面积及越壁范围检查通过。这些检查不覆盖大范围的正确泵驱动，不能作为候选可采用的证据。

- 候选帧末散度／动量 RMS 峰值约 `4.62e-14 / 5.09e-14`，冲量交换误差最大 `7.12e-9`，无越壁。
- 面积偏差最大从基线 2.00% 增至候选 13.54%；交接局部速度差最大从 0.179 增至 1.522 单位／秒。
- 两组每秒采样细胞中心最大差约 52.40 单位，存在明显行为改变。范围、边界驱动、反馈细胞数量和格距同时影响结果，不能将这些差异全部归于粗网格。
- 诊断只覆盖帧末和每秒观测，未验证全部子步、长期拥堵、真人手感或渲染帧预算。

结论：保留大窗口方向，优先解决域内泵驱动，再用相同配置复测。现有结果不支持为了性能提前退回近身小窗口，也不支持直接切换默认参数。

## 复现与归档

```bash
python3 docs/research/experiments/2026-10-27-wide-window/run.py --out /tmp/wide-window-replay
python3 docs/research/experiments/2026-10-27-wide-window/analyze.py --results /tmp/wide-window-replay
python3 docs/research/experiments/2026-10-27-wide-window/diagnose.py --results /tmp/wide-window-replay
rustfmt --check --edition 2024 docs/research/experiments/2026-10-27-wide-window/probe.rs docs/research/experiments/2026-10-27-wide-window/driver_audit.rs
```

`run.py`／`probe.rs` 保存匹配轨迹，`analyze.py` 核对来源、原始数据和统计；分析退出 0 表示归档数据符合上述数值范围，不代表大窗口流向验收通过。`diagnose.py`／`driver_audit.rs` 仅构建格距 0.5、小范围、零机械步的静态控制，不引入新驱动模型。

`results/` 包含正式来源快照、两组实际修改文件、主实验脚本快照、锁文件、命令、环境、二进制哈希、既有测试日志、原始 CSV、统计与静态控制输出。生产来源哈希保持；Python 语法、研究 Rust 格式及本地文档链接检查通过。未新增正式永久测试，未重跑 Godot／UI／全项目检查。
