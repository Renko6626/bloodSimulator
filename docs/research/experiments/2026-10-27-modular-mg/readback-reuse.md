# wgpu 回读缓冲复用：RTX 3060 匹配对照

用户要求先试现有 wgpu 下的资源复用。本轮只将 GPU MG 的状态／解回读缓冲改为准备时创建、后续复用，保留 shader、精度、命令边界、提交及回读次数。未新增通用内存池。

## 实现与验证

`MgSolver` 各持有一个 32 字节状态缓冲和一个 4N 字节解缓冲，N 为线性系统未知量数。每次只映射所需范围，取回数据后先释放 mapped view，再 unmap，随后才能作为下一次 GPU 拷贝目标。持久容量合计 32+4N 字节；创建成本计入准备阶段。

既有已知解／零 RHS smoke 会在同一个已准备求解器上反复求解，覆盖映射／解映射与重用；软件设备的真实 64² 两个 RHS 也在启用 GPU 时间戳时通过。`cargo test --offline --locked -p blood-fluid -p blood-fluid-gpu`、`cargo check --offline --locked --workspace` 和格式检查通过。未新增重复现有行为的永久测试。

云端恢复此前的 RTX 3060 实例，仍为 NVIDIA 580.65.06、Xeon E5-2683 v4、约 15.36 逻辑核配额。使用原冻结 Linux 输入，baseline 为已测 profiling 版的精确二进制，reuse 只改变上述生命周期。三规模、两区域、每域四 RHS、1／2 次 V-cycle、off／host、baseline／reuse、两轮反序交错，共 384 次求解。

所有记录均通过原方程 1e-4 检查；192 对前后版本的迭代数、停止残差、原方程／参考解诊断及 dispatch、提交、回读次数／字节数逐项相同。实际测量约 139 秒，cgroup 没有新增节流。宿主负载与 CPU／GPU 频率没有固定，仍保留共享主机波动的限制。

## 正常模式的总耗时

下表为关闭 profiling 时，每组 16 条记录的算术平均，单位 ms。匹配中位比为逐对 `reuse/baseline` 的中位数，小于 1 表示更快。

| 场景／V-cycle | baseline | reuse | 均值下降 | 匹配中位比 | 更快的匹配对 |
| --- | ---: | ---: | ---: | ---: | ---: |
| small64／1 | 56.12 | 45.80 | 18.4% | 0.830 | 16/16 |
| small64／2 | 81.82 | 70.98 | 13.2% | 0.857 | 15/16 |
| wide96／1 | 98.54 | 76.97 | 21.9% | 0.772 | 15/16 |
| wide96／2 | 131.39 | 115.06 | 12.4% | 0.863 | 15/16 |
| wide192／1 | 118.49 | 106.11 | 10.4% | 0.884 | 14/16 |
| wide192／2 | 200.56 | 183.63 | 8.4% | 0.922 | 11/16 |

六组均值均降低，观察到约 8%–22% 的净收益。384 条记录同时包含仪器化组；上表只使用其中的正常组，不能把主机计时组混入正常性能均值。这些是本轮同机匹配结果，不是对玩家设备的保证。

## 等待发生了迁移

以下为 host 组分段均值，单位 ms；左右为 baseline→reuse，不与上表拼成同一次求解：

| 场景／V-cycle | 回读准备 | 映射／poll | 未分项耗时 |
| --- | ---: | ---: | ---: |
| small64／1 | 13.75→0.09 | 5.85→13.41 | 5.26→0.02 |
| small64／2 | 13.45→0.09 | 12.25→18.41 | 4.64→0.02 |
| wide96／1 | 23.75→0.13 | 14.07→28.95 | 9.64→0.03 |
| wide96／2 | 20.34→0.15 | 28.71→41.51 | 8.02→0.03 |
| wide192／1 | 24.87→0.17 | 31.56→47.45 | 9.17→0.03 |
| wide192／2 | 24.63→0.15 | 56.37→72.07 | 8.10→0.03 |

求解中的 `create_buffer()` 已移除，但原先该 API 中的 wall time 有一部分移到了映射／poll 等待，不能将准备阶段下降全部当作节省。原未分项时间也显著下降；它与移除临时资源生命周期相符，本轮未单独测析构，不能将其精确归为某个驱动函数。

命令编码仍为大项，host 组 reuse 的编码均值约 30–101 ms。复用没有改变它需要处理的 pass／dispatch 数。单次求解仍明显慢于本场景复用固定 LU 因子的 CPU 路径；保留 CPU LU 默认。

准备阶段均值有波动：按场景／循环数，baseline 约 607–1,191 ms、reuse 约 616–1,236 ms，不能将其差异都归为这两个缓冲。该成本在已准备的求解器上跨 RHS 复用。

## 阶段结论

保留这项简单复用：它减少了热循环资源管理，并在本轮得到净收益。随后用户决定暂停研究，详见[统一阶段记录](../../2026-10-27-fluid-checkpoint.md)。命令组织、合并提交等仍是未验证讨论项，本轮未实施，也未改变算法／容差。
