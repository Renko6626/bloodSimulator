# Stokes 热路径优化独立审计

日期：2026-10-26。范围仅为本目录的独立研究程序；正式游戏、上轮 Rayon 实验及其数据不变。`baseline/`、`solver/` 和动态 harness 由其他 agent 维护，本审计只写 `review/`。

## 代码审阅

| 检查点 | 目前结论 |
| --- | --- |
| 方程与浮点顺序 | `solver/fluid.rs` 相对 `baseline/fluid.rs` 主要改变池安装位置、Schur 临时数组生命周期、prior 的借用和速度逆调用可变性。点阻力公式、散布/插值、压力/标记 CG 的 dot 与更新顺序未见改动。速度逆 FFT 每行以及 Thomas 每模式内部的运算顺序保持；静态完整场与最终逐帧输出均已验真一致。 |
| 持久缓冲 | 每次速度逆对整个 `re` 执行 `copy_from_slice(b)`，整个 `im` 执行 `fill(0.0)`；u 和 v 两段 mode 工作数组的 `n×rows` 项都在 gather 中覆盖，之后各模式解并按行全量散回，最后整个 `x` 被覆盖。`apply_s` 的 grad/ainvg 从每次算子调用新建改为每次 Stokes 解新建；离散 gradient、速度逆、divergence 均写满其有效数组。未见残留上一步状态的直接通路。 |
| Rayon 工作分隔 | 顶层 `solve` / `solve_lagged` 从 backend 临时取出私有持久线程池，在一次 `pool.install` 内执行所有速度逆，再将同一池放回；未逐次重建。FFT 行、mode 切片和最后回散的输出切片互不重叠，mode gather 只读原输入。粗任务的 `with_min_len(4)` 只改变调度粒度；未见并发写冲突。 |
| prior 与机械接口 | `solve_lagged` 将上一流场切片借给点采样，避免整场复制；首步无 prior 时新求背景场后借用局部结果。动态 harness 保留每子步冻结 marker、力律、`−F·Δt` 反冲量和 Rapier 推进。 |
| profiling | 两 variant 默认关闭，正式 runner 明确传 `--profile 0`。少量参考运行才启用；`velocity_inverse_ms` 是含四个速度逆子相位的外层计时，不能与子相位相加。`pressure_stencil_ms` 只计标出的 gradient/divergence，profile 运行不进入主性能汇总。 |

`solver/results/compare_baseline.csv` 包含 28 个匹配输入：32²/64²/128² 的 threads 0/1/2/4，profile 关/开各一组，再加 64² threads 0/2 的给定 prior 滞后组。全部速度、压力、点力、点速度及残差逐位相同，最大绝对差为零；两 variant 的流体调用数和迭代数一致。完整动态轨迹也与 baseline 一致。没有因理论角落提出额外状态机或永久测试。

## 主性能测量与独立复算

本轮 32 条正式轨迹均成功：`baseline`/`optimized` × threads `0/1/2/4` × 两轮 × 64²/128²。64² 每条 360 帧、128² 每条 120 帧，均为 16 细胞、弱阻力的相同滞后 Stokes 场景。每档 threads 的 variant 顺序在两轮互换，线程档次也由 `0→1→2→4` 变为 `4→2→1→0`。每条前 30 帧排除，64² 每路径汇总 660 帧、128² 汇总 180 帧。p95 对完整帧 `whole_ms` 用 nearest rank，阶段 p95 未相加。正式运行显式 `--profile 0`，没有 `profile.csv`；初始化和四种 CSV 输出在帧计时之外。四档 affinity 与上轮相同：threads 0/1 CPU2，2 CPU2–3，4 CPU2–5，四核同 socket、不同物理 core，单机非独占。

| 网格 | threads | baseline 整帧 mean / p95 / max (ms) | optimized 整帧 mean / p95 / max (ms) | 同线程均值倍速 |
| --- | ---: | ---: | ---: | ---: |
| 64² | 0 | 6.256 / 10.239 / 12.518 | 6.328 / 9.779 / 10.707 | 0.989× |
| 64² | 1 | 7.192 / 10.005 / 11.092 | 6.746 / 10.537 / 24.843 | 1.066× |
| 64² | 2 | 5.667 / 7.100 / 27.789 | 5.813 / 9.440 / 40.331 | 0.975× |
| 64² | 4 | 5.492 / 6.063 / 90.854 | 4.613 / 6.516 / 65.096 | 1.190× |
| 128² | 0 | 25.269 / 35.854 / 36.316 | 23.670 / 34.216 / 34.525 | 1.068× |
| 128² | 1 | 26.946 / 39.629 / 40.453 | 24.415 / 32.826 / 36.989 | 1.104× |
| 128² | 2 | 24.222 / 52.802 / 101.695 | 17.007 / 24.616 / 77.546 | 1.424× |
| 128² | 4 | 18.813 / 19.603 / 173.958 | 14.399 / 16.649 / 142.363 | 1.307× |

64² 四线程优化后均值 `4.613 ms`，但 p95 `6.516 ms` 比 baseline 的 `6.063 ms` 稍高，最大值仍 `65.096 ms`；不能称稳定达到整步 5 ms。64² 串行与双线程的本次均值略退，不能把优化写成所有线程档次通用提速。128² 四线程均值与 p95 下降，但仍约 `14.399/16.649 ms`，远高于 5 ms，且最大值 `142.363 ms`。尾部尖峰主要落在 `fluid_ms`；对比尖峰所在帧，流体调用数仍每帧 2，Rapier 和诊断时间没有相应跳升。单机非独占与前后反序只帮助识别运行顺序影响，不能确定峰值由系统调度、内存、工作分配还是组合造成，也不能把它们删掉再报性能。

主运行的 `process_cpu_seconds` 含初始化和文件输出，不是纯内核指标；四线程 64² baseline 两轮约 `4.94–5.14 s`，optimized `4.05–4.06 s`；128² 约 `5.08–5.27 s` 对 `4.41–4.43 s`。这说明本次整进程 CPU 消耗降低，不能直接拆解是哪一项热路径贡献。线程池构造独立计时且每轨迹只创建一次，64² 四线程 baseline 约 `0.317–0.326 ms`、optimized `0.456–0.510 ms`；128² 对应 `0.758–0.772 ms` 和 `0.847–0.908 ms`。优化版构造更慢的这一小项没有藏在整帧数里，频繁创建窗口时须另计，但本实验不包含窗口切换。

## Profile 参考范围

只对 64²、threads 0/4 的 baseline 与 optimized 各跑一条 120 帧 profile 轨迹；剔前 30 帧后仅 90 帧。每帧两子步合计速度逆调用数均为 14。四线程的平均 `mode_gather_solve_scatter_ms` 从约 `1.949` 降为 `1.094 ms`，准备/复制从 `0.243` 降为 `0.146 ms`，`pressure_stencil_ms` 从 `0.298` 到 `0.287 ms`。四线程 `velocity_inverse_ms` 从 `3.729` 降为 `2.527 ms`，**这个总项包含四个速度逆子相位，不能再与它们相加**。

还有一个更关键的计时边界变化：baseline 的 `velocity_inverse_ms` 在每次速度逆外层计时，包含那一次 `pool.install`；优化版将 `pool.install` 移到整个 Stokes 更新外层，`velocity_inverse_ms` 不再包含该入口，但 `fluid_ms` 和 `whole_ms` 仍包含它。因此总项的降幅既有实际热路径变化，也有计时归属变化，不能全解释为消灭的工作。特别是四子相位之外的 `velocity_inverse_ms` 余额从约 `0.348` 到 `0.006 ms`，主要反映该边界迁移；`mode_gather_solve_scatter_ms` 比较口径更接近，但多项优化同时发生，90 帧 profile 也不是单项消融实验。串行 profile 的 inverse 总项反而从 `4.928` 到 `5.657 ms`，与正式串行没有提速的总体情况相容，不能只挑四线程 profile 讲故事。

## 数值一致性和实际命令

独立脚本逐条检查正式轨迹连续帧号、`t≈frame/60`、有限值；删去四项计时列后，32 条轨迹的全部逐帧列与同网格 baseline threads0 第一轮一致。`cells.csv`、`outlines.csv`、`fields.csv` 在相同帧数的正式轨迹间逐字节一致；64² baseline threads0 第一轮的三份文件也与上轮 Rayon 实验归档一致。manifest 的 19 个源/锁文件及两份已保存二进制的 SHA-256 均匹配。该证据支持缓冲复用没有在所测连续轨迹中留下历史污染，且优化未改离散动力学；不把一条轨迹提升为所有未来输入的证明。

实际运行只读复算：

```bash
python3 docs/research/experiments/2026-10-26-stokes-hotpaths/review/recompute.py
```

脚本退出码 0，输出各轮与合并的整帧 mean/p95/max、静态逐位核对结果和 profile 原始均值；没有重新跑性能测试。另以只读 Python 对两份保存二进制的 SHA-256、尖峰帧的阶段时间和 manifest `process_cpu_seconds` 复查。

## 限制

即使数值轨迹一致，本实验仍只覆盖单位方域周期直管、16 个软体细胞、有限阻力可渗透点及本机 CPU。优化是否帮助不规则血管、更多近景细胞和正式游戏整体 5 ms，尚不能由本轮直接证明。profile 是少量带 instrument 的参考运行，主表才是未带 instrument 的正式测量。
