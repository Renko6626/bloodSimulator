# Rayon 准稳态 Stokes 独立审计

日期：2026-10-26。仅审查独立研究程序的线程化和实测结果；正式游戏、旧实验及其输出不在本次修改范围。`solver/` 与 `dynamics/` 由其他 agent 维护，本审计只写 `review/`。

## 代码路径审阅

| 项目 | 已确认事实 | 适用边界 |
| --- | --- | --- |
| 常驻线程池 | `SeparableInverse::with_threads(n, 1/2/4)` 建一个私有 `ThreadPool` 并存在求解器内；每次速度逆调用 `pool.install`。`threads=0` 不建池，走复制自上轮的串行 FFT/Thomas 循环。池在帧循环外、Stokes 构造时建立。 | 需把初始化时间单列；每次 `install` 与调度仍计入流体和整帧。 |
| 并行数据分割 | x 向 FFT 对不重叠的行切片操作。Thomas 前将 row-major 数据搬成每个 Fourier 模式独占的连续切片，各模式独立作前代/回代，再按行写回。读取原数组与写入 mode 数组分离；散回时行切片不重叠。 | 源码未见同一输出的并发写入。转置、额外两块数组分配和调度是 Rayon 1 的额外成本，不能把 Rayon 1 变化都说成并行收益。 |
| 方程保持 | 与上一轮 `solver/fluid.rs` 的 diff 只增加线程数构造路由；marker 点力、散布/插值、dot、Schur CG 和收敛阈值未改。新动态 `main.rs` 的 diff 只增加 `--threads`、求解器构造与初始化计时；机械、流体子步、反冲量和整帧计时采样位置未改。 | 点力和 CG reduction 仍串行，因此并行只覆盖规则通道速度逆；不能称整套耦合求解全并行。 |
| 数值单次核对 | `solver/results/numerical_check.csv` 的 32²、64²、128² 各 threads 1/2/4，共九组；速度、压力、点力、标记采样数组与新求解器 threads 0 **逐位相等**，调用/迭代计数、最终散度/动量/阻力律残差一致。 | 验证该固定16细胞多点快照；动态逐帧轨迹仍需最终 CSV 核对。 |
| 核拓扑 | 本机 `lscpu -e=CPU,CORE,SOCKET,NODE` 显示 CPU 2、3、4、5 为同一 socket 0、不同物理 core 2、3、4、5；CPU 58 是 CPU 2 的 SMT 同胞。 | 只有 runner 实际使用 `taskset` 并记录亲和性时，这一拓扑事实才支持线程比较。 |

## 最终原始数据复核

`run.py` 的 16 次正式运行均退出 0：64²、16 细胞、滞后阻力各 360 帧；128² 同场景各 120 帧。每种网格第一轮按 threads `0→1→2→4`，第二轮反序 `4→2→1→0`。程序先检验 CPU 2、3、4、5 在同一 socket 的不同物理核，实际分别给 threads 0/1 绑定 CPU 2、threads 2 绑定 CPU 2,3、threads 4 绑定 CPU 2–5。Rayon 工作者继承进程 affinity，没有逐线程单独绑核。主机非独占；相邻两轮存在机器负载变化，不能把小差值当成稳定硬件保证。

旧动态 harness 的 `whole_ms` 包含每帧两个物理子步、点构建、流体、Rapier 与帧诊断；所有 CSV 写入在采样之后。新动态 `main.rs` 与旧版 diff 显示该计时边界未变。线程池在帧循环前创建，`init.csv` 单列初始化时间。前 30 帧作为热身不进入计时统计，因此 64² 每个运行 330 样本、每种线程合并 660 样本；128² 每个运行 90 样本、合并 180 样本。p95 是合并完整帧的 nearest-rank 分位数，未由阶段 p95 相加。下表的最大值也只来自热身后帧。

| 网格 | 路径 | 整帧 mean / p95 / max (ms) | 相对原串行 mean 倍速 |
| --- | --- | ---: | ---: |
| 64² | 原串行 threads 0 | 6.403 / 9.894 / 14.844 | 1.000× |
| 64² | Rayon 1 | 7.136 / 10.095 / 10.776 | 0.897× |
| 64² | Rayon 2 | 5.775 / 8.155 / 33.404 | 1.109× |
| 64² | Rayon 4 | 5.612 / 7.217 / 37.336 | 1.141× |
| 128² | 原串行 threads 0 | 25.435 / 36.049 / 36.192 | 1.000× |
| 128² | Rayon 1 | 28.927 / 40.079 / 40.201 | 0.879× |
| 128² | Rayon 2 | 20.499 / 39.993 / 128.435 | 1.241× |
| 128² | Rayon 4 | 18.566 / 22.391 / 130.533 | 1.370× |

Rayon 1 比原串行均值慢约 11%（64²）和 14%（128²）：它包括 mode 转置、额外数组分配、`install` 和任务调度，不能把这一步叫作并行提速。Rayon 4 相对 Rayon 1 的均值倍速约 `1.27× / 1.56×`，说明多个工作线程确实缩短这一实现的整步用时，但扩展幅度有限；相对原串行净收益为 `1.14× / 1.37×`。两网格的整步 mean 和 p95 均超过 `<5 ms` 目标，64² 四线程甚至 mean `5.612 ms`。

尾部不可用均值掩盖。64² 四线程第二轮第 347–349 帧整步约 `32.27/36.76/37.34 ms`；128² 四线程两轮各有 `122.51` 和 `130.53 ms` 热身后峰值，另有一个两线程 `128.43 ms` 峰值。峰值基本落在 `fluid_ms` 内，流体调用数仍为每帧 2，所有物理输出与原串行相同；资料不能确定它由线程调度、内存、系统其他负载或组合造成。已有只读系统记录显示所检查 cgroup 的 quota 无限且 `nr_throttled=0`，不支持把峰值直接归为该 cgroup 的 CPU 限额；同样没有证据把它们全部归为外部噪声。128² 四线程包含热身帧的最大值另达约 `141.22 ms`，上表有意按排除热身的计时口径列 `130.533 ms`。

线程池构造时间：64² 原串行两次约 `0.141–0.153 ms`、Rayon 4 约 `0.292–0.448 ms`；128² 对应 `0.519–0.534 ms` 与 `0.926–1.002 ms`。此成本未计入整帧，但若局部流场频繁新建就不能免费忽略。本轮每个运行只构造一次。`process_cpu_seconds` 含初始化和输出，在 64² 两轮中原串行约 `2.22–2.43 s`、Rayon 4 约 `4.41–4.46 s`；128² 原串行约 `2.99–3.10 s`、Rayon 4 约 `5.12–5.24 s`。它说明本次总 CPU 消耗增加，不能当作纯速度逆内核的 CPU 周期拆分。

## 数值与轨迹一致性

独立脚本对所有 16 个 `frames.csv` 检查帧号、时间戳和有限值，重算每次及合并的整帧 mean/p95/max；逐帧删除四个计时字段后，其余全部列与同网格第一轮原串行记录相同。每个运行的 `cells.csv`、`outlines.csv`、`fields.csv` 与该串行记录逐字节相同；64² 新串行的三份文件也与上一轮归档的 `lagged64-16` 逐字节相同。这涵盖了点受力、残差、冲量、Rapier 状态和输出轨迹的记录精度。实验 manifest 的 11 个源文件 SHA-256 均与现存源码匹配；单次非平凡多点数值核对还显示原生解数组逐位相等。未见线程化引起物理方程或离散轨迹变化。

实际执行的独立只读命令：

```bash
python3 docs/research/experiments/2026-10-26-stokes-rayon/review/recompute.py
```

脚本退出码 0。另用只读 Python 对 manifest 的 11 个源文件重新计算 SHA-256，并检查尖峰所在帧的 `whole_ms`、`fluid_ms`、`rapier_ms` 和 `stokes_fluid_calls`，均与上文一致。未重新跑性能测试或修改其他 agent 的目录。

## 适用范围与未验证项

Rayon 只加速规则周期通道的 FFT/Thomas 速度逆；点力、CG、Rapier、任意固定不规则墙和开放端口未并行或未实现。128² 测量只有每轮 90 个计时帧；合并 p95 与最大值均是本次非独占机器的观察值。两轮反序有助于查看顺序偏差，不能给目标玩家设备的延迟上界。正式游戏与后端没有改动，本结果不足以批准正式接入或声称近景几十个细胞整体小于 5 ms。
