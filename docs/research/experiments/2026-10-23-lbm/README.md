# D2Q9 LBM research archive

See the [Chinese experiment report](../../2026-10-23-lbm-experiment.md) for the current conclusions. `main.rs` is the baseline; `optimized.rs` implements the same numerical method with precomputed fixed-wall streaming links. All seven measured optimization cases have identical non-timing outputs and identical field CSVs.

Reproduce from the repository root:

```bash
python3 docs/research/experiments/2026-10-23-lbm/run.py --cpu 2 --blocks 30
python3 docs/research/experiments/2026-10-23-lbm/run_optimized.py --cpu 2 --blocks 30
python3 docs/research/experiments/2026-10-23-lbm/plot.py
```

The runners build into temporary directories and overwrite their result files. Existing NumPy/Matplotlib are needed only for analysis and plots. The measurements are in [baseline samples](results/samples.csv), [optimized samples](results/optimized/samples.csv), [baseline summary](results/summary.csv), [optimized summary](results/optimized/summary.csv), and [independent analysis](results/analysis.json). Environment JSONs record source hashes and CPU/compiler information. All times exclude Godot and Rapier. The 30 samples per case are consecutive fixed-geometry model-time blocks after one initial settle, not independent moving-cell gameplay runs.


This is a throwaway, std-only Rust experiment. It does not change the product solver. Build with `rustc -O main.rs -o lbm`. Examples: `taskset -c 3 ./lbm --n 32 --scene straight --force-amplitude 0.1 --field straight-32.csv`, the same with `--scene channel`, and `taskset -c 3 ./lbm --n 32 --scene blob4 --gamma 0.25 --marker-speed 0.1 --post-steps 103 --post-repeats 30 --post-samples post.csv --field blob4-g025-32.csv`. The output is one CSV header and row. A nonconverged or unstable run exits 2; its row still gives the steps and residual. Defaults: `n=32`, `scene=straight`, `force-amplitude=0.1` (automatically zero for blob4), `tau=1`, `gamma=.25`, `marker-speed=.1`, `post-steps=0`, `post-repeats=1`, `max-steps=200000`, `window-time=0.01`, `threshold=1e-5`. Initialization is at rest.

Physical domain is `[0,1]^2`, density reference 1, kinematic viscosity 1, periodic x and stationary solid y walls. D2Q9 BGK uses Guo forcing and half-way link bounceback; the channel's binary solid mask follows `bottom=.12+.04sin(2πx)`, `top=.88−.08sin(2πx)` at cell centers. This staircase/link wall is **not** the earlier Brinkman permeable volume wall, so their error or solve times are not direct wins for either method. The reported `re_l1` is measured maximum physical speed times domain length 1 divided by viscosity 1. For `force-amplitude=.1`, Re is small but not identically zero; the curved-channel field need not exactly match Stokes.

`dx=1/n`, `nu_lu=(tau-.5)/3`, `dt=nu_lu dx²`, `force_lu=force_amplitude dt²/dx`, and `u_phys=u_lu dx/dt`. Density reference and physical kinematic viscosity are both 1. LBM steps are viscous time substeps, **not game ticks**. `steps_to_t1=ceil(1/dt)` gives the total steps required for the same physical time 1 even if steady stopping occurs elsewhere. Every run starts from rest. Steady checks use a window rounded from `.01/dt` steps and `R=RMS(u(t)-u(t-window))/(window*dt)/(Uscale*nu/L²)`, with `nu=L=1` and `Uscale=force-amplitude` for straight/channel or `marker-speed` for blob4. Stop only after physical time at least 1 and three consecutive windows with `R<1e-5`. `max_steps` produces explicit failure, not an assumed steady state.

`init_ms` is mask/allocation/setup. `solve_ms` is the whole LBM march to first steady stop, including steady checks, excluding diagnostics and field export. `us_per_fluid_cell_step=1000 solve_ms/(fluid_cells*settle_steps)` is an amortized value, not a single game-step cost. `--post-steps` sets steps per block; `--post-repeats` repeats that block continuously from steady state, with no reset or settle between blocks. Each block includes point force updates. Summary `post_steps`, `post_physical_time` and `post_ms` are **totals** across all completed blocks; `post_block_steps` is requested steps per block, `post_repeats` is completed blocks, and `post_ms_mean/p95` summarize block elapsed times. p95 uses nearest rank. `--post-samples path.csv` writes `block,steps,physical_time,elapsed_ms` after timing, so CSV I/O is excluded. At n32 and tau1, `ceil((1/60)/dt)=103`, giving physical duration 0.0167643 per block. This is a frozen-geometry, steady-update cost baseline, not an accurate moving-cell game tick; it includes no Rapier work and is not multiplied by two for Rapier substeps. One settle followed by repeated blocks can estimate the update-time distribution, but gives one cold-start observation and no cold-start p95. Archived repeated measurements use nonexclusive CPU 2; the initial CPU 3 smoke observations are superseded by those data.

`blob4` has no background force and four fixed point locations `(0.425,.5)`, `(.575,.5)`, `(.5,.425)`, `(.5,.575)` prescribed to move at `(marker-speed,0)`. Total point resistance is `gamma`, each point has `r=gamma/4`. The four-point Peskin kernel interpolates **LB cell-center** velocity and spreads each physical force `F=r(V−Ju)` as force density `wF/dx²`; it is not the earlier MAC face kernel. Every LBM step recomputes F from the preceding state's velocity, including its preceding Guo half-force. Collision uses the new force with `rho_lu u=Σ f_i c_i+F_lu/2`, `F_lu=F_phys_density dt²/dx`. This one-step lag is iterated during physical relaxation; it is not the old MAC calculation of one feedback solve from zero. `reaction_x/y=-ΣF` acts on the prescribed object. `force_balance_abs` is the magnitude of reaction plus integrated scattered fluid force. `force_law_velocity_relative_rms=RMS(F/r+Ju−V)/|V|` uses final field velocities, so it exposes any residual lag. The points do not move, no Rapier dynamics are calculated, and this is a finite-resistance permeable coupling rather than a membrane.

For the straight pipe, Poiseuille reference is `u=f y(1-y)/2`, flux `f/12`; the L2 uses cell centers and includes transverse velocity. `wall_velocity_extrapolated` is quadratic extrapolation from the first three cell-center velocities to the half-way lower wall, not a velocity stored at the wall. `density_min/max` and mass error use fluid sites only. `div_center_fd_rms` is centered finite difference of primitive cell-center velocity where all four neighbors are fluid; it differs from the earlier MAC face-divergence norm and does not test its discrete incompressibility equation. The field export contains physical cell-center `x,y,u,v,p,density,solid`; solid values are zero. Pressure is `c_s,phys²(ρ−1)`, with an arbitrary constant reference.

Actual numerical fields are in `results/fields/` and `results/optimized/fields/`. Fixed-link optimization reduces per-step CPU overhead; changing τ also changes the required step count and discretization error, so these two effects are reported separately.
