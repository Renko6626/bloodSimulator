# 可玩血管路网草图任务

用户已指出当前128条微血管重复、缺少游戏性，要求类似城市开放世界路网的复杂度，确认器官各有特色、跨器官任务方向；设备和任务系统本轮暂停。用户已同意保留24/12/6/3管径分级与流量守恒/统一求解，放开严格1→4→16→64、等长对称和固定均流模板，按可玩路网重新校准速度。

本轮只交付全图交通骨架草图、心脏—肺部周边细化图及对应设计说明，不修改生产地图或实现新系统。旧地图保留为数值/装卸验证场。现有心脏真实轮廓与接口可参考`existing-heart.svg`和`map/heart.rs`，图中的旧外部管道不带入新设计。

## 目标

- 通过目的地关系、区域尺度的环路/横向联络、多入口和非对称路径提供选择；不再复制扇形树或简单把树排成网格。
- 24主干连接区域；12构成器官周边交通；6承担主要局部探索；3只在少量有说明的特殊通路出现。实际管径画出比例，不画成等粗地铁图。
- 主要选区地形至少能解释几种明显不同的走法，且目的地/入口有名字能认路。心脏—肺部区域先细化，其他区只保留交通骨架和器官预留范围。
- 心脏维持现有四腔尺寸、至少80单位的心室可深入跨度；保留四类接口的逻辑归属。可以整体平移作为绘图排版，但不能缩成小图标，需有比例尺/一屏视野参照。
- 心脏和肺部名称已确定；其他区域标“器官预留区A/B”等，不擅自确立具体肝肾位置、形状或真实生理功能。器官分区阴影不是流体腔室，图例明确区分。

## 关键约束

- 当前二维模型中，管道相交就是实际连通。不能画假立交、无标记跨越或靠颜色假装分层；有意交叉均标真实路口，其他道路留管宽净间隔。规划图仍待实装SDF净空检查，不宣称物理已验收。
- 右房→右室→肺侧网络→左房→左室→体侧网络→右房的两循环串联逻辑保留。左右心腔间不得靠新联络路贯通，也不能画一条绕过肺侧或体侧局部网络的主干短接。
- 多环路/横联优先在同一供血侧或同一回流侧形成；供回连接是明确规划的器官局部交通/微循环区域，不能在主干之间无意加上宽直通短路。玩家通行可双向，血流方向和数值留待统一求解，不画伪造流场。
- 不固定Q48/参考压差/各支路流速；旧基准表仍作调参参考而非整图硬约束，不以人工局部限速作弊。任何将来采用的额外抽象循环/虚拟管道/跨层模型都须另行方案，本草图不采用。
- 不新增任务/设备/敌人/掉落/传送/单向阀或事件状态机。可说明路段未来适合何种内容，但必须标为意图。不要用未批准的机制来赋予道路不存在的通行规则。
- 世界范围随空间关系确定，建议比现有1424×2719的重复验证图更紧凑；无需追求大数字。说明心脏到肺部和主要入口的大致距离/步行时间（当前主动速度4），这些仅是设计估算，不是实际回放。
- 固定16单位区块、地图/实体5×5和实时LBM3×3不变；不引入新引擎/地图配置格式、图路由框架、生成器、编辑器或求解器。
