# CPU NS、GPU LBM 与 GPU NS 实验路线

创建：2026-10-27；更新：2026-10-28。**用户已确定采用 GPU LBM，后续工作转向应用方案；详见[阶段决策](lbm-decision.md)。** 此前先 LBM、再 GPU NS 的比较安排保留为历史研究路线，GPU NS 不再作为采用 LBM 的前置条件。第一批 CPU NS 实验已完成；完整 192²／256² 的当前实现超出实时预算。详见 [NS 首批结果](ns-results.md)。已完成 [Vast CPU profile](profile/README.md)，热点集中于插值权重与三个串行因子求解；云实例已停止。

## 研究目标

本轮希望在实时游戏的约束下尽量保留血流的物理特征：动脉考虑几十到几百雷诺数下的惯性和脉动，毛细血管考虑低雷诺数下的黏性流动、细胞变形和受阻。具体数值应按选定血管的尺度与流速标定，不能给整个地图统一指定一个 Re。

本轮重新讨论流体模型与推进方法。上一阶段的 Stokes／GPU 性能研究保留为参照，不沿用其优化待办作为新实验安排。历史入口是[流体实验阶段记录](../2026-10-27-fluid-checkpoint.md)，本轮讨论另参考了 [gpt-advice.md](../../../gpt-advice.md)。

## 已确认的路线选择

**CPU NS 与 GPU LBM 首批实验已完成；用户已确认 GPU LBM 方案可行，将应用于游戏。具体接入方案尚待确定，正式游戏尚未切换。**

2026-10-28 用户确认上述优先级。CPU NS 保留为对照基线，权重／缓存等局部优化暂不作为主线。此次先确认实验顺序。随后用户已确认 GPU LBM 使用 Rust＋wgpu 27／WGSL、D2Q9 MRT＋Guo 外力，首批规则域与 72 细胞实卡实验已完成，见 [LBM 结果](lbm-results.md)。GPU NS 的具体算法仍待其阶段确认。

| 顺序 | 路线 | 要回答的问题 | 选择理由与主要代价 |
| --- | --- | --- | --- |
| 1（首批已完成） | CPU MAC 投影法 NS 基线 | 加入惯性和流场记忆后，能否覆盖动脉与低 Re 工况，并与现有软体共同运行？ | 可复用 Rust、MAC 网格和固定几何，CPU 与 Rapier 交换方便；需要验证对流、黏性推进、压力边界与时间离散 |

| 3（补充对照，非采用前置） | GPU NS 投影法 | 保留当前物理模型和 MAC 定义，GPU 推进能否满足精度与完整成本要求？ | 复用 CPU NS 对照；需要选择适合 GPU 的黏性／压力求解方案，并控制任务与同步开销 |

Stokes 在微循环中仍有物理意义，保留为低 Re 参照。完整 NS 本身也能描述低 Re 流动；无需因为存在两类血管，就立即实现两套生产路径。

本轮继续沿用 Rust 模拟与 Godot 表现层的既有分工。具体离散、求解算法、重要依赖和模块调整在相应阶段再研究、记录并按项目约定确认。

## 阶段一：建立 NS 实验基线

先建立独立、固定实验域，按以下顺序逐步增加内容：

1. 明确物理尺度、流速、黏度和脉动条件，分别定义动脉与微循环的代表工况。
2. 从无细胞的稳态、脉动流动开始，检查速度、流量和时间响应，再加入能体现对流与惯性的场景。
3. 接入现有 Rapier 软体，检查细胞运动、反作用及流量变化，辨别流体推进与细胞耦合各自的误差。
4. 在物理表现可信的候选上测完整推进成本，区分流体、耦合、Rapier、初始化与研究诊断。

阶段产出应说明：采用了什么模型、在哪些工况可信、主要误差与成本在哪里，以及哪些结果可供 LBM 对照。NS 阶段取得可用的对照基线后进入 GPU LBM；不要求先把 NS 优化到最终性能。

## 阶段二：建立 GPU LBM 对照

复用 NS 阶段选定的代表场景、物理参数和观测指标，先验证流体推进，再加入细胞交换。GPU 计算、CPU 等待和回读共同计入成本。

LBM 必须按实际物理时间统计全部格子步，不能只比较一次 kernel 或一个格子步。记录实际 Re、格子速度、黏度与密度变化，避免通过改变物理条件获得表面上的速度优势。

阶段产出应说明：目标工况下所需子步、稳定范围、物理误差及完整闭环耗时。GPU API、碰撞模型、外力和开口边界的具体方案留待本阶段研究。

## 阶段三：GPU NS 补充对照（保留研究方案）

以下为原对照计划；LBM 已确定采用，GPU NS 不再承担是否采用 LBM 的决策门槛。本次阶段记录不启动该实验，具体开展安排待明确。沿用 CPU NS 基线的物理参数、MAC 网格定义与解析验证，评估对流、黏性和压力投影在 GPU 上连续推进的完整成本。

实现前先比较黏性与压力线性求解方案，不把直接迁移 CPU Cholesky 回代视作已确认实现。复用现有 GPU 设备、profiling 与回读设施，明确观察旧 Stokes 实验暴露的命令编码、小任务和同步开销。

先验证无细胞场景，再加入软体交换。记录误差、收敛、子步数、GPU 时间、主机编码／等待和回读；精度或耦合频率与 CPU 基线不同时单独说明。GPU API、线性算法与重要依赖尚未确定。

## 阶段四：LBM 应用与接入方案

LBM 已确定采用。后续明确模拟域、开放边界和游戏接口；若继续 GPU NS 对照，在相同物理工况和相近效果精度下比较，以现有 CPU NS 作为数值与性能参照。完整 192²／256² 为主要规模，窄通道按真实活跃格子数另报。对照包括低 Re 和动脉代表工况；性能同时报告均值、p95 和完整模拟步成本，不用跨设备、跨场景的旧计时计算加速倍数。

60 Hz 下“流体、耦合与必要等待的 p95 约 5 ms”保留为候选预算，尚非正式验收承诺。最终预算还需结合目标设备、Rapier 和渲染成本确定。

决定接入前，明确模型仍然保留的近似、覆盖范围和运行成本。区域交接、全图反馈或不同血管使用不同求解器，若确有必要，再作为后续方案讨论。

## 贯穿各阶段的判断

- **尺度与画面分开核对。** 同时关注 Re、脉动的 Womersley 数及细胞直径与管径之比。当前主干约为五个细胞直径，不能仅提高 Re 就称为真实动脉；二维通道也不等同于三维圆管。
- **细胞耦合需要独立检验。** 少量有限阻力点允许透流，可以作为起点，尚未证明满足毛细血管的拟真要求。若观察到模型缺口，再提出更合适的耦合方案；不预设增加点数就能实现不可渗透膜。
- **驱动条件必须对应问题。** 测阻流时区分固定压差下的流量下降与固定流量下的压差增加。显式细胞与背景流体的黏度含义也需说明，避免重复计入细胞阻力。
- **非定常流场保留历史。** 旧 Stokes 的背景／反馈线性叠加，以及只传递阻力历史的双区域切换，不能直接作为 NS／LBM 的推进和交接方法。
- **验证按阶段需要展开。** 从简单参照到实际负载，检查物理误差、网格与时间步影响；发现具体问题再追加调查，避免一开始铺开全部参数组合。

## 调研入口

- [动脉 Reynolds 与 Womersley 数研究](https://link.springer.com/article/10.1007/s13239-024-00723-4)：物理相似性与脉动标定。

- [毛细血管细胞流动研究](https://experts.arizona.edu/en/publications/flow-dependent-rheological-properties-of-blood-in-capillaries/)：细胞变形、壁面间隙与流动阻力。

## GPU LBM 首批完成（2026-10-28）

RTX 3060 完成 18 解析工况与 20 次性能轨迹。Re=100 完整 192²／256²、72 细胞的流体加耦合 p95 约 2.44／3.93 ms，整步 6.77／8.83 ms，不含渲染；低 Re 窄通道仍超候选预算。[结果与限制](lbm-results.md)。新实例 57988490 结果取回后确认 stopped／exited。GPU NS 尚未实现，具体求解方案仍在实施前确认。
