# CPU NS Vast profile

2026-10-27，用户明确安排开始 profile，随后指定转到 Vast 主机执行。已通过 API 实例 ID、容器标签及 SSH 核对实例 57949215，RTX 3060 12GB / Xeon E5-2683 v4，CPU 配额 15.36 核。使用现有项目 SSH key，原历史实验不改。目标是解释完整 192²／256² 超预算的来源，不更换物理模型、求解器或生产架构。

1. 保留首批结果、源码快照与原始 release 二进制，核对基线。
2. 记录采样工具权限。perf 在沙箱内及获批的沙箱外均因主机 perf_event_paranoid=4 拒绝；不改变主机内核配置。使用仅针对本进程的 CPU 定时器采样，捕捉各线程正在执行的指令地址；记录丢样／定时器延迟，避免把占比当成精确耗时。
3. 在研究 lab 内增加可关闭的分段观测：对流、速度 u/v 黏性求解、压力 RHS／求解／修正、耦合、Rapier、诊断。分别记录墙钟、全进程 CPU、主线程 CPU。采样与数值逻辑分离，默认关闭。
4. 保持原物理参数，直接测 192²／256² + 72 细胞，固定 CPU 2–5；对比 1／4 个 Rayon 工作线程，以判断并行与调度开销。控制组不采样，采样组只用于定位热点，不能混入性能验收。
5. 核对观测开关、线程数变化后的数值终态，保存命令、源码和二进制哈希、原始数据、热点与结论。只提出有证据的后续优化，不在本轮替换算法。

原始地址采样只给出 self PC 热点，不生成伪造的调用栈／火焰图；没有硬件计数器就不宣称缓存带宽或 IPC 的测量结论。

云端使用本地构建的相同 x86-64 release 程序，上传实验源码／锁文件／二进制与哈希；不传 `.env`。先跑原始二进制复测，再跑可关闭观测组。GPU 仅记录设备状态，本批 CPU NS 本身无 GPU kernel；不把 GPU 空闲当成遗漏的 CPU profile。完成后取回结果、核对文件哈希，再调用 Vast stop 并等待实际停止。

## 云端观测边界

- 云端 /usr/bin/perf 是缺少对应内核工具的包装器；直接 perf_event_open 自进程 user-space task-clock 探针也返回 EPERM。确认容器无所需能力后不改宿主策略。
- sample.c 使用各线程 CLOCK_THREAD_CPUTIME_ID 的约 499 Hz 定时器、SIGEV_THREAD_ID 和信号上下文的 RIP 采样，LD_PRELOAD 包装 pthread_create 以覆盖 Rayon 线程。只在 120/240 帧测量区的命名阶段记录，初始化和 30 帧热身排除；样本与精确 ELF／maps 归档。无硬件计数器、无调用栈。
- 在 profile.rs 中单独记录全进程／主线程 CPU 时间。进程 CPU 包含工作线程执行与自旋，墙钟包含调度与等待；两者不能直接相减作为精确 idle 时间。所有阶段串行标记，不把子计时加到父项上。
- 原始 baseline、修改后观测 off、detail 的四线程组，以及 off/detail 的单线程组，192²／256² 各两轮反序。采样另跑 240 帧。72 细胞、同初态与两个子步保持；单线程改变的是 Rayon 工作线程数量，faer 仍为 Par::Seq。
