# GPU LBM 阶段决策：确定采用

日期：2026-10-28。用户明确结论：“我们 LBM 方案是靠谱的，会被应用。”本文记录本阶段的路线决定，作为后续工作的入口。

## 已决定

**GPU LBM 已确定用于本项目的游戏流体模拟。后续讨论以如何应用为出发点，不再把是否采用 LBM 作为悬而未决的问题。**

当前已确认并完成首批实验的技术路线为 Rust＋wgpu 27／WGSL、D2Q9 MRT＋Guo 外力，沿用 Rust 模拟与 Godot 表现层分工。代码仍在独立研究程序中，正式游戏尚未接入；确定采用不等于接入已经完成。

原路线图的 GPU NS 对照仍可提供补充参考，但不再作为确定采用 LBM 的前置条件。本次只做阶段记录，不启动 GPU NS、额外实验、云实例或游戏接入工作。

## 决策依据

[GPU LBM 首批实卡结果](lbm-results.md)已归档。RTX 3060、Re=100、完整 192²／256²、72 个细胞：

| 指标 | 192² | 256² |
| --- | ---: | ---: |
| 每个 60 Hz 帧的格子步 | 28 | 36 |
| 流体＋耦合＋必要等待 p95 | 2.44 ms | 3.93 ms |
| 整步 p95，含 Rapier 与研究诊断 | 6.77 ms | 8.83 ms |

整步不含渲染和游戏逻辑。18 个解析工况与 20 次性能轨迹完成，原始结果和来源已核验。该证据支持本项目采用路线，不代表所有几何、设备或长期运行都已验收。Re=0.1 的高黏度窄通道成本较高这一结果保留，不用改写实验条件消除负结果。

## 游戏尺度讨论的阶段位置

- 用户提出从游戏性和效率出发选择管径、流速、黏度，优先考虑主动脉／次级动脉风格场景；“Re 几到几百”是讨论方向，尚未定为全地图或每时刻必须满足的参数约束，也未完成生理尺度标定。
- 用户提出心房／心室级开阔区域的玩法价值，以及模拟区域与外部血流交换的问题。后续范围设计应纳入这些需求，不能默认把所有区域都压缩进一屏。
- 当前代码：玩家直径 1.7 单位，细胞初始直径 1.4 单位；默认视口 1280×800、24 像素／单位，约 53.3×33.3 单位。
- 64×48 单位／256×192 格只是此前提出的局部覆盖候选；“完整固定腔室＋短连接血管、镜头独立移动”也是建议，均未确认成最终域架构。不得据本记录直接实施移动窗口、分级耦合或房间调度。

## 应用时待确定

模拟域按完整腔室还是局部范围组织；开放边界如何连接外部血流；域大小与网格精度；大腔室、分叉及玩法驱动；正式游戏接口与目标设备预算。这些具体方案按项目约定在实施前确认，无需重新确认采用 LBM 本身。

现有细胞四点有限阻力仍允许透流，真实封堵、排液和薄层流动没有实现。当前独立实验仍使用规则周期域，不能把窗口裁剪边缘当成血管固壁来替代开放边界。后续围绕实际玩法缺口做有针对性的验证，不默认扩展为全面生理仿真。

## 保留状态

CPU NS／Stokes 与原始实验记录保留为参考；上一阶段 GPU Stokes 优化仍暂停。默认游戏仍是现有解析血流路径，显式局部 Stokes 路径保留。新云实例 57988490 已取回结果并确认 stopped／exited，磁盘保留，见[停机回执](lbm-vast/stop.json)。
